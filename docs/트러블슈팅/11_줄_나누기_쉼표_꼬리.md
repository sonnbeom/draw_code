# 11. 두 줄 품명에서 쉼표가 마침표로, 아랫줄에 부스러기

> 5단계 줄 모드 `bom/cell_image.py` `split_by_valley` 구현 중. 설계는 [19](../설계/19_OCR_전략.md)

## 증상
- 영어 모델 줄 모드 품명 74.8%. 틀린 것 대부분이 두 줄 품명에서 `,` → `.`, 아랫줄 끝에 `:` 또는 `(` 빠짐
  - case_0603 행4 `RIVET-BLIND. D4.8 X L11.5 - TYPE A:` (정답 `RIVET-BLIND, D4.8 …`)
  - case_0612 행11 `BACK FRAME SUB ASSY. RH DLX)` (정답 `…, RH (DLX)`)
- 그림 보고서를 보니 아랫줄 그림 오른쪽에 점 하나가 찍혀 있음

## 원인
- 이 폰트의 쉼표 = 세로 획(2.3) + 꼬리 획(1.07, 비스듬히 아래로)
- 줄 자르는 높이(골짜기)가 윗줄 바닥 = 꼬리의 위 끝(1047.82)과 같음
- 처음 규칙 "획 가운데 y가 자른 높이보다 아래면 아랫줄" → 꼬리가 아랫줄로 감. 위 끝 기준으로 바꿔도 꼬리 위 끝이 자른 높이와 같아 여전히 아랫줄
- 결과: 윗줄 쉼표는 꼬리 없는 점(`.`)이 되고, 아랫줄에 꼬리가 점으로 남아 OCR이 `:`로 읽거나 줄을 넓혀 `(`를 놓침

## 해결 후보
| 후보 | 장점 | 단점 |
|---|---|---|
| 자르는 높이를 아래로 여유 | 간단 | 여유값이 도면마다 다를 수 있음. 아랫줄 윗부분을 뺏을 수 있음 |
| **끝점이 윗줄 획과 닿은 획은 윗줄로** (같은 글자) | 쉼표·괄호 등 모양에 상관없이 "이어진 획 = 한 글자" | 위아래 줄 글자가 실제로 닿으면 섞임 (아직 못 봄) |

**결정.** 위 끝 기준으로 나눈 뒤, 윗줄 획과 끝점을 공유하는 획은 윗줄로 옮긴다 (더 안 옮겨질 때까지)

## 결과
- 샘플 0601~0650 품명 정확 74.8% → **92.4%** (느슨 76.3% → 95.3%)
- 품번·I/NO·수량 그대로

## 교훈
- 숫자만 보면 "OCR이 쉼표를 못 읽는다"로 보였는데, 그림 보고서로 입력 그림을 보니 우리 줄 나누기 문제였다. 정답률이 낮으면 모델보다 입력부터 본다
