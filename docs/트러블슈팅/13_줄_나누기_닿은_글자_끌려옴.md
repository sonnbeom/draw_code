# 13. 쉼표 꼬리에 닿은 아랫줄 글자가 윗줄로 끌려옴

> 5단계 줄 모드 `bom/cell_image.py` `split_by_valley`. [11](11_줄_나누기_쉼표_꼬리.md)의 "닿은 획은 윗줄로" 규칙이 만든 문제

## 증상
- 테스트 도면 88500 행8·9·10 품명: 첫째 줄 그림에 둘째 줄 글자 하나가 같이 그려짐 (줄 그림 높이 86px, 보통 48)
  - 행8·9: `TRACK ASSY, RH` + 쉼표 밑의 `M` (둘째 줄 `+IMS+`)
  - 행10: `TRACK ASSY, RH (RHD)` + 쉼표 밑의 `2` (둘째 줄 `+2_L`)
- 샘플에서는 안 나옴

## 원인
- 이 도면은 줄 간격이 0: 첫째 줄 바닥 = 둘째 줄 꼭대기 (글자 높이 대비 1.16)
- 쉼표 꼬리 끝(1.31)이 둘째 줄 `M`·`2`의 꼭대기 점과 닿음
- [11](11_줄_나누기_쉼표_꼬리.md)의 규칙은 "윗줄 획에 닿은 획은 윗줄로"를 더 안 옮겨질 때까지 반복 → 꼬리 → `M` 획 → … 글자째 끌려옴

## 해결 후보
| 후보 | 결과 |
|---|---|
| 반복 없이 한 번만 옮기기 | ✗ 행10은 고쳐지지만 행8·9의 `M`은 꼬리가 아니라 쉼표 획에 바로 닿아 그대로 끌려옴 |
| 짧은 획만 옮기기 (길이 < 0.5) | ✗ `M`(획 길이 1.0)은 고쳐지지만 `2`는 곡선이라 짧은 조각들로 그려져 줄줄이 끌려옴 |
| **자른 높이 바로 밑(0.3 안)에서 끝나는 획만 옮기기** | ✓ 쉼표 꼬리는 0.21까지만 내려옴. 아랫줄 글자 획은 0.4 넘게 내려감 (`M` 1.0, `2` 첫 조각 0.44) |

**결정.** 세 번째. 상수 `TAIL_MAX = 0.3`

## 결과
- 88500 행8·9·10 모두 줄이 바르게 나뉨
- 샘플 0601~0820 OCR 결과 그대로 (품명 99.5%, 품번 느슨 100%), 테스트 도면 다른 줄 그림 그대로

## 교훈
- "닿으면 같은 글자" 규칙은 줄 간격이 0인 도면에서는 위아래 줄 글자도 닿아서 깨진다. 닿음 + 위치(얼마나 내려왔나)로 함께 판단한다
- 획 길이는 글자 모양(직선 / 곡선 조각)에 따라 달라 기준으로 약하다. 위치가 더 안정적
