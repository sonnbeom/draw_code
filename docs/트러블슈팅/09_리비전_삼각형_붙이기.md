# 09. 리비전 삼각형을 못 찾거나 못 붙임

> 4-2 `bom/strikes/revisions.py` 구현 중. 설계는 [12](../설계/12_리비전_삼각형.md)

## 증상
1. 테스트 도면 6개 전부 삼각형 0개
2. 고친 뒤에도 22000 NO 3 행 `△07 △04 △01` 중 `△01`만 붙음
3. 28440·88400 상위 맨 위 행 삼각형이 안 붙음
4. 22000 NO 23 행 `△03 △01` 중 `△03`이 안 붙음

## 원인
| 증상 | 원인 |
|---|---|
| 1 | `geometry.length`는 **가로 변화량 + 세로 변화량**(가로·세로선용). 비스듬한 변은 실제 31.5가 43으로 재져 정삼각형으로 안 보임 |
| 2 | 삼각형이 여러 개면 **왼쪽으로 줄지어** 붙는다. 표에 닿는 건 맨 오른쪽뿐, 나머지는 오른쪽 삼각형에 닿음 (표에서 31~62 떨어짐) |
| 3 | 삼각형이 행보다 큼 (변 33, 높이 28.5 > 행 28.3). "삼각형 전체가 행 안" 조건에서 위로 2.5 삐져나와 탈락 |
| 4 | 삼각형끼리 0.6 겹침. 간격 허용이 -0.5 (`TOUCH_TOL`) |

## 해결 후보
| 증상 | 후보 | 결정 |
|---|---|---|
| 1 | `geometry.length`를 피타고라스로 바꿈 / 삼각형만 따로 실제 길이 | **따로** (`_true_length`). 기존 판정(1~3단계)이 지금 길이 기준으로 맞춰져 있음 |
| 2 | 표에서 거리 늘리기 / **이미 붙은 삼각형도 붙일 대상으로** | 후자. 오른쪽 삼각형부터 차례로 붙임. 거리만 늘리면 그림 속 삼각형이 섞임 |
| 3 | 행 범위 여유 / **가운데 y로 행 판정** | 후자. 칸 판정(`find_slot`)과 같은 방식 |
| 4 | 겹침 허용 = 글자 높이 × 0.1 (0.92) | 채택 |

## 결과
- 테스트 6개 기댓값대로 (그림으로 확인, 88500은 한 자리 숫자)
- 샘플 817/818 = json, 나머지 1개(0797)는 삼각형 위에 다른 글자 `15`가 겹친 샘플 결함 → 검수로 표시됨

## 교훈
- 공용 함수의 정의(여기선 "길이")가 새 용도에 맞는지 docstring을 먼저 본다
- 기댓값을 그림으로 적을 때도 놓칠 수 있다 (88400 상위 `△07`). 규칙을 고친 뒤 새로 나온 결과는 그림으로 다시 확인
