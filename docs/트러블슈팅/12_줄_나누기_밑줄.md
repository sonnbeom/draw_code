# 12. 윗줄의 밑줄 `_`이 아랫줄로 넘어감

> 5단계 줄 모드 `bom/cell_image.py` `split_by_valley`. 설계는 [19](../설계/19_OCR_전략.md), 앞 문제는 [11](11_줄_나누기_쉼표_꼬리.md)

## 증상
- 떨어진 `-` 확인 중 테스트 도면 88500 행14 품명 셋째 줄에 양옆 간격 4.74인 `-`가 나옴
- 칸 전체: `TRACK ASSY, RH (RHD)` / `(8WP+2_L/SUPT+…+USB` / `2)` → 셋째 줄 `2)` 옆의 선은 둘째 줄 `2_L`의 밑줄
- 그대로 두면 둘째 줄은 `2 L`, 셋째 줄은 `2) -`로 읽힘
- 샘플 json 품명에 `_`가 0개라 샘플에서는 안 보였음

## 원인
- 이 도면은 줄 간격이 좁음: 둘째 줄 바닥 2.16, 밑줄 2.23, 셋째 줄 꼭대기 약 2.3 (글자 높이 대비)
- 골짜기(획 수 최소)에서 자르면 자른 높이가 밑줄보다 위 → "위 끝이 자른 높이보다 아래면 아랫줄" 규칙으로 밑줄이 아랫줄로 감
- 밑줄은 다른 획과 안 닿아서 [11](11_줄_나누기_쉼표_꼬리.md)의 "닿은 획은 윗줄로"도 안 걸림

## 해결 후보
| 후보 | 결과 |
|---|---|
| 골짜기 구간의 가운데에서 자르기 | ✗ 밑줄은 고쳐지지만 88500 행4 `…USB2` / `)`가 한 줄로 합쳐짐. 아랫줄이 `)` 하나뿐이면 획 수 1인 구간이 아랫줄 안까지 이어져 가운데가 `)` 아래로 감 |
| 홀로 획(끝점이 아무 획과도 안 닿음)은 가운데 높이가 가까운 줄로 | ✗ `+`의 가로·세로 획은 끝점이 아니라 가운데서 겹쳐 홀로로 잡힘 → `+`가 깨짐. 네모 겹침으로 바꿔도 윗 덩어리가 두 줄이면 가운데가 멀어 밑줄이 여전히 아랫줄 |
| **아랫줄 글자 꼭대기 + 0.25 위에 있는 홀로 가로 획은 윗줄로** | ✓ 아랫줄 자기 `-`(+0.5)·`_`(+1.0)는 꼭대기에서 멀어 안 움직임 |
- 홀로 = 가로 획이고 다른 어떤 획과도 감싸는 네모가 안 겹침 (`+`의 가로 획은 세로 획과 겹쳐 제외)

**결정.** 세 번째. `_lift_underscores`, 상수 `UNDERSCORE_TOP = 0.25`

## 결과
- 88500 행14: `_`가 둘째 줄로 돌아감, 셋째 줄은 `2)`만
- 샘플 0601~0820 OCR 결과 그대로 (품명 99.5%, 품번 느슨 100%), 테스트 도면 줄 그림 수·취소선 확인 그대로

## 교훈
- 샘플(프로그램으로 만든 도면)에 없는 글자(`_`)와 좁은 줄 간격은 테스트 도면에서만 나온다. 줄 나누기 규칙은 테스트 도면 그림으로도 확인한다
- 첫 고침(가운데 자르기)은 다른 칸을 망가뜨렸다. 고친 뒤 높이가 큰 줄 그림 수를 옛 방식과 나란히 비교해서 잡음
