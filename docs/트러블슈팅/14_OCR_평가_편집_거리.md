# 14. 칸 정답률만으로는 얼마나·무엇을 틀렸는지 모름 → 편집 거리 (DP, 바그너-피셔, 역추적)

> 5단계 OCR 평가 `explore/measure_ocr/metrics.py` + `compare_readers.py`. 학습 계획 [OCR 23](../OCR/23_학습_계획.md) 5절

## 증상
- `compare_readers`는 칸마다 맞음/틀림만 셈 (품명 2756/2761)
- 학습 전/후를 비교하려면 부족함
  - 한 글자 틀린 칸과 전부 틀린 칸이 똑같이 "틀림 1칸"
  - 어떤 글자를 어떤 글자로 잘못 읽는지(`D`→`O`인지, 새 오독이 생겼는지)는 사람이 예시를 눈으로 봐야 앎

## 원인
- 칸 정답률은 "같다 / 다르다" 두 값뿐. 두 문자열이 **얼마나** 다른지, **어디가** 다른지를 재는 기준이 없음

## 해결 후보
### 1. 무엇으로 잴까
| 후보 | 식 | 결과 |
|---|---|---|
| 칸 정답률 (지금) | 맞은 칸 ÷ 칸 수 | ✗ 틀린 정도·종류를 모름 |
| 유사도 | 1 − 거리 ÷ **더 긴 쪽** 길이 | △ 두 문자열이 닮은 정도. 나누는 수가 칸마다 달라 여러 칸을 합치기 어려움 |
| **CER (글자 오류율)** | 거리 합 ÷ **정답** 글자 수 합 | ✓ 기준이 정답이라 전/후 비교, 열별·전체 합산 가능. OCR 평가에서 보통 씀 |

**편집 거리 (레벤슈타인 거리)** = got을 want로 만드는 최소 수정 횟수. 수정은 세 가지, 각 1회
| 수정 | 실제 예 | 거리 |
|---|---|---|
| 바꾸기 | `M8X2S` → `M8X25` (`S`→`5`) | 1 |
| 빼기 (OCR이 더 읽음) | `(3- STEPS)` → `(3-STEPS)` (공백) | 1 |
| 넣기 (OCR이 놓침) | `` → `-` (칸 모드가 한 글자 칸을 못 읽음) | 1 |

### 2. 어떻게 계산할까
규칙 (재귀): 끝 글자부터 봄
- 한쪽이 비면 → 다른 쪽 길이
- 끝 글자가 같으면 → 앞부분끼리의 거리 (비용 0)
- 다르면 → 1 + min(바꾸기: 둘 다 한 글자 줄임, 빼기: got만 줄임, 넣기: want만 줄임)

| 후보 | 결과 |
|---|---|
| 재귀 그대로 | ✗ 한 번에 세 갈래로 나뉘어 같은 앞부분 쌍을 수없이 다시 계산 (글자 수에 대해 지수적으로 늘어남) |
| 재귀 + 메모 (위에서 아래로) | △ 다시 계산은 없어지지만 깊은 재귀 (Java의 `HashMap` 메모와 같음) |
| **표를 작은 것부터 채움 (아래에서 위로, 바그너-피셔)** | ✓ 반복문 두 개. 칸 수 = (got 길이+1) × (want 길이+1) |

**결정.** CER + 표 채우기. 이렇게 "작은 문제의 답을 표에 저장해 큰 문제를 푸는" 방법이 **동적 계획법(DP)**. 편집 거리를 DP 표로 푸는 방법의 이름이 **바그너-피셔 알고리즘**

## 표 채우기 (바그너-피셔): `OLX` → `DLX`
`dp[i][j]` = got 앞 i글자 → want 앞 j글자 최소 횟수. 빈 문자열 행·열이 있어서 표 i행의 글자는 `got[i - 1]`
| got \ want | `""` | `D` | `DL` | `DLX` |
|---|---|---|---|---|
| `""` | 0 | 1 | 2 | 3 |
| `O` | 1 | 1 | 2 | 3 |
| `OL` | 2 | 2 | 1 | 2 |
| `OLX` | 3 | 3 | 2 | **1** |
- 첫 행·첫 열: 한쪽이 비었으니 0, 1, 2, 3
- 칸마다 세 이웃을 봄: **왼쪽 위 = 바꾸기**, **위 = 빼기**, **왼쪽 = 넣기**
- `O`→`D`: 다름 → 1 + min(왼쪽 위 0, 위 1, 왼쪽 1) = 1
- `OL`→`DL`: `L`=`L` → 왼쪽 위(1) 그대로
- 오른쪽 아래가 답: 거리 1

## 역추적: 어떤 수정을 했는지 꺼내기 (혼동 목록)
- 거리는 숫자 하나뿐 → "무엇을 틀렸나"는 표를 **오른쪽 아래에서 왼쪽 위 (0, 0)까지 거꾸로** 따라가며 "이 값이 어느 이웃에서 왔나"로 알아냄
```
OLX→DLX (1)  X=X       → 왼쪽 위로, 수정 없음
OL→DL   (1)  L=L       → 왼쪽 위로, 수정 없음
O→D     (1)  왼쪽 위 0 + 1 → 바꾸기 (정답 D, 읽음 O)
```
- 판단 순서: 같은 글자 → 왼쪽 위 +1 (바꾸기) → 위 +1 (빼기) → 나머지 (넣기). 최소 경로가 여러 개면 이 순서대로 하나를 고름 (바꾸기 우선)
- 결과는 `(정답 글자, 읽은 글자)` 쌍 목록. 빼기는 `('', 읽은 글자)`, 넣기는 `(정답 글자, '')`
- **수정 목록의 길이 = 편집 거리** → `compare_readers`는 `edit_ops`만 부르고 `len()`으로 거리를 얻음 (표를 두 번 안 만듦)
- 열마다 `Counter`로 쌍을 세면 혼동 목록 (`D→O 5`)

## 결과
- `metrics.py` 자체 확인 12/12 (거리 6 + 수정 목록 6, 위 표의 실제 오독들)
- 0601~0820 학습 전 기준 (정확 기준, 0/O 틀림 포함): 전체 CER 0.049% (58/118172)
  - 품번 0.174%, 혼동 `O→0` 36 · `0→O` 17
  - 품명 0.007%, 혼동 `D→O` 5
  - I/NO·수량 0%
- 틀린 글자가 품번 0/O, 품명 D→O 두 종류뿐임을 숫자로 확인 → 학습 목표는 품명 `D→O` 0 (자세한 표는 [OCR 23](../OCR/23_학습_계획.md) 5절)

## 교훈
- 맞음/틀림 하나로 세면 개선이 "몇 칸"으로만 보임. 거리(얼마나) + 수정 목록(무엇을)을 같이 봐야 학습 전/후에 새 오독이 생겼는지까지 알 수 있다
- 나누는 수를 정답 길이로 고정해야 여러 칸·여러 실행을 합치고 비교할 수 있다 (유사도가 아니라 CER)
- 재귀 규칙을 먼저 세우고 → 같은 계산이 반복되면 표로 바꾸는 것이 DP의 기본 흐름. 표가 남아 있으면 역추적으로 "답이 어떻게 나왔는지"도 꺼낼 수 있다
