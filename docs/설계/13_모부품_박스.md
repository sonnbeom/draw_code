# 13. 모부품 박스: 품번 + 오른쪽 품명

## 문제
모부품 하나 = 박스 안 **품번** + 박스 **오른쪽**의 **품명** (+ 왼쪽 rev 삼각형, [12](12_리비전_삼각형.md)). 품명은 박스 밖에 있고, 그 자리에 연결선이 지나간다.

**case_0002 좌표**
```
박스 3개가 위아래로 쌓임: x 585~693, 가로선 y 687.4 / 705.8 / 724.3 / 742.7
박스 안 품번:  x ≈ 597~682
오른쪽 품명:   x ≈ 702~845 (각 박스와 같은 높이)
연결선: 박스 오른쪽 끝(x 693)에서 수평 → x 741.3 / 769.6 / 798.0에서 꺾여 수직 → 표 위(y 670.4) 화살표
```

## 1. 품명이 어느 박스 것인가
**결정.** 박스의 **y범위 안**에 있고 **박스 오른쪽**에 있는 선 = 그 박스의 품명 (범위 겹침 재사용)

## 2. 품명 자리를 지나가는 연결선
- 바로 아래: 그 박스 자신의 수평 연결선 (y 696.6)
- 가로지름: 위쪽 다른 박스들의 연결선이 수직으로 내려가며 품명 줄을 관통 (x 769.6, 798.0)
- 그대로 두면 세로선 때문에 글자들이 하나로 묶인다

**결정.** 연결선을 지우고 읽는다
- 연결선은 표 찾기([03](03_표_찾기.md))에서 이미 찾았으므로 빼기만 하면 된다
- 연결선은 길고 수평/수직, 글자 획은 짧아 구분된다
```
"규칙으로 찾은 선은 지우고 읽는다"
  취소선 → DEL 기록 후 제거  (06)
  삼각형 → 숫자 읽기 전 제거 (12)
  연결선 → 품명 읽기 전 제거 (13)
```

## 3. 박스 안 품번
**결정.** 박스도 가로선·세로선으로 둘러싸인 **칸**이므로 표 칸과 같은 방식으로 읽는다
- index_no 칸: slash_pno 216개 중 104개에만 있음 (standard·slash_qty_assy는 없음). 있으면 읽고 없으면 비움
- 박스 안 칸 나누기가 표와 같은지 구현 때 확인

## 전체 흐름
```
박스 (표 찾기에서 이미 찾음)
 ├ 박스 안 칸 → 품번 (+ index_no)
 ├ 박스 y범위 + 오른쪽 선 → 연결선 제거 → 품명
 └ 왼쪽 삼각형 → rev
```

## 4. 상위가 표인 경우 (테스트 도면 88500)
**문제.** 상위가 박스가 아니라 `I/NO | PART NO | PART NAME | NOTE` **표**(25행)이고, 행마다 선이 하위 표 수량 열로 내려간다. 박스 전용 규칙으로는 못 다룬다.

| 패턴 | 도면 | 모양 |
|---|---|---|
| A. 박스 | 28440(2), 88361(4), 88400(8), 22000·88300(1) | 박스 → 꺾인 선 → 수량 열 위 화살표 |
| B. 표 | 88500 | 상위 표의 각 행 → 꺾인 선 → 수량 열 위 화살표 |
| 그 외 | 사용자 보유 | 미확인 |

**결정.** 두 패턴을 하나의 규칙으로: **상위 항목(박스 또는 상위 표의 행)의 y범위에서 출발한 선을 끝점 따라 추적**한다. 품명은 박스면 박스 오른쪽, 표면 그 행의 PART NAME 칸.

## 5. 연결 추적 규칙
글자 인식과 연결은 별개 작업이고 둘 다 선 좌표에서 출발한다. 둘을 잇는 것은 위치 범위 겹침(**공간 매칭**).
```
상위 항목 y범위 ∋ 수평선 시작
→ 끝점을 공유하는 선을 따라감
→ 화살표 끝 x ∈ 수량 열 x범위 (머리글 아래 열 경계 기준, [03](03_표_찾기.md) 4절)
→ 그 열 × 하위 표 각 행의 칸 값 = 수량 ("-"는 미포함)
```
- **수평/수직으로 판정하지 않는다.** 88500 맨 위 두 행의 선은 약 4pt 기울어짐 (x 5005.0 → 5009.1, 끝 y 743.5). "완전한 수직선"만 찾으면 놓친다
- 교차(선 중간에서 만남)와 꺾임(끝점에서 만남)은 좌표로 구분된다. 88500은 계단 모양이라 교차 없음

**88500 실측**
```
상위 표 행 경계 y: 112.8 ~ 715.2, 24.1 간격, 25행 (위에서 23-1, 23, 22, … , 2, 1)
수평선: 상위 표 오른쪽 끝 x 4406.0에서 출발, y = 각 행 가운데
화살표 끝 y 740.7 ("QTY" 머리글 위). 수량 열 경계 x: 4439.8부터 24.1 간격 (끝 5042.2)
```
| 상위 행 (위에서) | 수평선 y | 화살표 x | 수량 열 |
|---|---|---|---|
| 1번째 (23-1) | 124.8 | 5033.2 | 25 |
| 2번째 (23) | 148.9 | 5009.1 | 24 |
| 3번째 (22) | 173.0 | 4975.8 | 23 |
| … | … | … | … |
| 24번째 (2) | 679.0 | 4471.3 | 2 |
| 25번째 (1) | 703.1 | 4450.9 | 1 |
- 25/25 끝점 공유, 서로 다른 열에 1:1. 위 행일수록 오른쪽 열
- 검산 1: 88500-NR520(y 667.0~691.1) → 2열 → 하위 2행 88101-NX560 ×1. 두 품명 옵션 `(8WP+2_L/SUPT+HTR+USB2)` 일치
- 검산 2: 수량이 취소된 12열·23열 = 상위에서 취소된 12행(88600-NR690)·22행(88500-NR680)
- 예외: 상위 6행(88500-NR050, 이 도면 자신의 품번)은 취소됐는데 6열 수량엔 취소선 없음 → 구현 때 확인

**OCR로 연결도 할 수 있나?**
| 방법 | 결과 |
|---|---|
| 일반 OCR | 글자+위치만, 선은 안 읽음 |
| 표 구조 인식 모델 | 표 하나 안의 칸용, 표 사이 연결선은 대상 아님 |
| 이미지에서 선 검출 | PDF에 있는 정확한 좌표를 뭉갰다가 다시 추정 |
| 멀티모달 LLM | 평행선 25개가 2~3pt 간격으로 붙으면 틀리기 쉽고 틀렸는지 모름 |

**결정.** 연결은 선 좌표 추적. 글자는 좌표만으론 뭔지 몰라 인식이 필요하지만, 연결은 좌표 자체가 답이다.
- 도면 간 연결(하위 품번이 다른 도면의 상위 품번): 품번 일치로 이을 수 있음. 테스트 6개 안에서는 짝 미발견, 범위 밖
