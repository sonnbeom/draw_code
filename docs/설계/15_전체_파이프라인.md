# 전체 파이프라인: 도면 PDF → BOM xlsx

## 문제 정의
- 입력: 도면 PDF (벡터). 글자가 텍스트가 아니라 **선(CAD 스트로크 폰트)**으로 그려져 있다
- 출력: BOM (모부품 + 자부품 행)을 case_XXXX.xlsx와 같은 구조로
- 데이터: 샘플 PDF 820개 + 정답 json, 테스트 도면 6개 (정답 없음, [01](01_데이터_파악.md))

## 전체 흐름 (2026-11-17 갱신: 글자 읽기 = OCR)
```
   ┌──────────────── 선 좌표 (위치·구조) ────────────────┐      ┌ OCR ┐
PDF → ① 선 추출 → ② 표 찾기 → ③ 칸 나누기 → ④ 연결 추적 → ⑤ 규칙 처리 → ⑥ 글자 읽기 → ⑦ 조립·검사 → ⑧ xlsx
                    (+머리글 OCR)                                                       │
                                                     ML: 칸 신뢰도 ──────────────────────┘
                                                     ML: 표 종류 분류 (②, 종류가 늘면)
평가: test PDF → ①~⑧ → json과 비교
```
- 위치·구조는 선, 글자 내용은 OCR. 둘을 잇는 것은 위치 범위 겹침(공간 매칭)
- ⑤가 ⑥보다 먼저: 방해 선을 지워야 OCR이 깨끗한 글자를 읽는다

---

## ① 선 추출 ([02](02_PDF구조와_OCR.md))
**문제.** 텍스트 추출이 안 된다.

**결정.** 선 좌표 `(x1, y1, x2, y2, 색)`. 글자 읽기만 OCR ([02](02_PDF구조와_OCR.md) 문제 3)
- 선분은 `m`/`l`만 있음 (곡선·사각형 없음)
- 색: 샘플 검정 `0 0 0`, 파랑 `0 0.314 1`, `0 0.353 0.706`. 테스트 88500 파랑 `0 0 1` → 색 값을 고정하지 말고 "검정이 아닌 색"으로

## ② 표 찾기 ([03](03_표_찾기.md))
**문제.** 선 수천 개 중 BOM 표는 어디인가? 표제란·리비전 기록란·상위 표도 같은 격자다.

**결정.** 선으로 후보 → 머리글만 OCR → 연결선으로 확인
```
길고 + 수평/수직 (허용 오차)          → 글자·도형 제외
끝점이 맞닿은 묶음                    → 표 후보
머리글 OCR: 품번 계열 + 수량 계열      → 하위 BOM (품번만 = 상위 표·표제란 후보)
연결선: 화살표가 닿음 = 하위, 출발 = 상위 → 머리글 판단과 다르면 경고
```
- 열 역할은 순서가 아니라 **머리글 이름**으로 (88500에 MATERIAL 열 추가). 같은 뜻 다른 표기는 이름 사전
- 표 종류가 늘면 분류기로 ([03](03_표_찾기.md) 6절)

## ③ 칸 나누기 ([03](03_표_찾기.md), [13](13_모부품_박스.md))
**결정.** 격자 가로선 사이 = 행, 세로선 사이 = 열. 모부품 박스도 칸으로 취급한다.
- 수량 머리글이 여러 열을 덮을 수 있음 → 열 경계는 머리글 아래 선으로

## ④ 연결 추적 ([13](13_모부품_박스.md))
**문제.** 상위 품번 ↔ 하위 수량 열. 상위가 박스(패턴 A)일 수도 표(패턴 B, 88500)일 수도 있다.

**결정.** 상위 항목 y범위 ∋ 수평선 시작 → **끝점 공유로** 따라감 (수평/수직 판정 X, 기울어진 선 있음) → 화살표 끝 x ∈ 수량 열 x범위
- 88500에서 25/25 매핑, 옵션 문자열·취소 열로 검산됨

## ⑤ 규칙 처리 ([06](06_취소선.md), [12](12_리비전_삼각형.md), [13](13_모부품_박스.md))
**결정.** 글자가 아닌 선을 규칙으로 찾아 **기록하고 지운 뒤** 글자를 읽는다.

| 대상 | 찾는 법 | 기록 |
|---|---|---|
| 취소선 | 행 가운데 높이에서 글자를 가로지르는 수평선. 수량 칸 하나짜리 짧은 것도 있음 (88500) | `[DEL]` |
| 리비전 삼각형 | 닫힌 세 선 + 정삼각형 + 밑변 수평 + 크기 (변 ÷ 글자 높이 비율) | 안 숫자 내림차순 `(02,01)` |
| 연결선 | ④에서 이미 찾음 | 없음 (품명 줄을 가로질러서 지움) |

## ⑥ 글자 읽기 ([02](02_PDF구조와_OCR.md))
**문제.** 칸 안의 선들을 문자열로 바꿔야 한다.

**결정.** OCR. 입력은 ⑤에서 지운 선을 뺀 획만 그린 칸 이미지 (또는 clip 렌더링, 미정)
- 위치는 칸 좌표로 유지
- 직접 학습은 **보류**. 샘플 val 칸 정확도가 부족하면 미세조정 또는 기존 분류기 설계([07](../보류_글자학습/07_정규화.md)~[11](../보류_글자학습/11_데이터_품질.md))를 꺼낸다
- 미정: OCR 엔진, 입력 이미지, 칸 단위 vs 표 단위

## ⑦ 조립·검사 ([12](12_리비전_삼각형.md), [13](13_모부품_박스.md), [14](14_평가.md))
**결정.**
- **표 행:** `no` (+ ` (02,01)`, + ` [DEL]`) / `part_no` / `part_name` / `quantities` {모부품 품번: 값}
- **모부품:** 박스면 박스 안 칸 → `part_no`, 오른쪽 선 → `part_name`. 상위 표면 그 행의 칸
- `[BLUE]`는 출력하지 않음
- 칸마다 **신뢰도** (아래 ML) → 기준 초과면 검수 표시. 머리글에서 품번·품명·수량을 못 찾거나, 화살표 수 ≠ 상위 항목 수면 경고

## ⑧ xlsx 출력
case_XXXX.xlsx와 같은 구조 + 검수 표시(칸 색칠, 검수 열, 검수 목록 시트). 셀 배치는 구현 때 샘플로 확인.

## 머신러닝 (결과를 믿을 수 있나)
원래 ML은 글자 인식 하나 때문이었고, OCR이 대신한다. ML은 판단 층에 쓴다.

| | 칸 신뢰도 ([14](14_평가.md) 5절) | 표 종류 분류 ([03](03_표_찾기.md) 6절) |
|---|---|---|
| 하는 일 | 칸마다 "틀렸을 확률" | 격자 후보 → 하위 BOM / 상위 / 표제란 / 리비전 기록란 / 기타 |
| 왜 | 정답 없는 도면에서 어디를 검수할지 | 엔지니어마다 새 종류의 표가 나올 수 있음 |
| 특징 | OCR 자신감, 형식, 같은 표 품번 계열, 중복, no 순서, 상위↔하위 옵션 일치 등 | 행·열 수, 비율, 위치, 머리글 단어, 연결선, 글자 방향 |
| 라벨 | json 비교로 자동 | BOM·상위는 json, 나머지는 수작업 |
| 모델 | 로지스틱 회귀 | 작은 선형/트리 |
| 시점 | ⑥ 이후 | 규칙으로 먼저, 규칙이 틀린 사례가 모이면 |

- 분할: **PDF 단위** train/val/test = 70/15/15
- 신경망은 직접 만들지 않음 (OCR 엔진 자체는 신경망)

## 평가 ([14](14_평가.md))
**결정.**
| 항목 | 방법 |
|---|---|
| 데이터 | test PDF, 마지막에 한 번만 |
| 점수 | **행 정확도 (주 점수)** / 칸 정확도 (칸 종류별) / 글자 정확도 (진단) |
| 행 짝짓기 | no로 짝지음 (도면 안에서 no 중복 0건). 못 짝지은 행은 품번·순서로 2차 |
| 버리기 | 안 버림. 개수가 안 맞아도 틀린 걸로 셈 |
| 원인 가르기 | 위 단계부터: 행·열 수 다름 → 표 찾기 / 내용만 다름 → OCR |
| 신뢰도 점검 | 검수 표시의 정밀도·재현율, 보정(점수 = 실제 오류율인가) |

## 구현 순서
| 순서 | 만들 것 | 확인 방법 |
|---|---|---|
| 1 | ① 선 추출 | matplotlib으로 다시 그려 원본과 비교 |
| 2 | ② 표 찾기 + ③ 칸 나누기 (선만) | BOM 표만 색칠해서 그려 보기, 행 수 = json `num_items` |
| 3 | ④ 연결 추적 | 88500 25/25 재현, 샘플 수량 열 수 = `num_parents` |
| 4 | ⑤ 규칙 처리 | DEL·rev가 json과 일치 |
| 5 | ⑥ OCR (+ ②에 머리글 OCR 추가) | 샘플 val 칸 정확도, 혼동 글자 목록 |
| 6 | ⑦ 조립 + ⑧ 출력 + 평가 | test 행 정확도, 단계별 원인 개수 |
| 7 | ML 칸 신뢰도 | val 정밀도·재현율, 보정 |
| 8 | ML 표 종류 분류 (패턴이 모이면) | 규칙 대비 정확도 |

## 구현 때 확인할 것
- OCR 엔진이 이 폰트에서 0/O, 1/I, `-`를 구분하는지 (22000 품번 끝 글자)
- 사선 머리글(slash_pno, slash_qty_assy)을 OCR이 읽는지, 사선이 격자 묶기에 끼어드는지 ([03](03_표_찾기.md))
- 다른 연결 패턴에서도 끝점 추적이 통하는지, 교차 vs 꺾임 ([13](13_모부품_박스.md))
- 88500 상위 6행(취소)인데 6열 수량엔 취소선 없음
- 삼각형 크기 비율, 두 줄 품명 줄 간격의 실제 값
- 모부품 박스 안 칸 나누기가 표와 같은가 ([13](13_모부품_박스.md))
- 88361처럼 2쪽짜리 도면의 처리
