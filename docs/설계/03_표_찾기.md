# 03. 표 찾기

## 문제
선 수천 개(글자 선 / 표 칸 선 / 도형 선) 중 BOM 표를 찾아야 한다. 표제란·리비전 기록란·모부품 박스도 같은 격자 모양이다.

## 0. 화살촉을 선에 합치기 (2026-11-18)
테스트 도면은 연결선 끝의 화살촉 때문에 세로선이 BOM 윗변과 8.5 떨어진다 → ① 거르기 **전에** 화살촉으로 들어오는 선의 끝을 꼭짓점까지 늘린다 (`bom/arrows.py`).
- 화살촉 = 선 3개로 닫힌 삼각형 + 바깥 선 끝이 한 변의 30~70%에 닿음 + 그 선이 반대쪽 꼭짓점을 향함 (크기·모양·칠하기 안 씀)
- 후보는 넓게(치수선 화살촉도 늘림), 확정은 BOM 고르기에서 (꼭짓점이 BOM 윗변에 닿은 것만 연결선)
- 문제·후보·결과: [트러블슈팅 04](../트러블슈팅/04_화살촉_틈.md)

## 1. 표 칸 선 후보 거르기 (갱신 2026-11-18)
| 조건 | 제거되는 것 | 예 (case_0001) |
|---|---|---|
| **수평 또는 수직**, 기울기 3° 이하 | 비스듬한 선 (case_0001 2,003개) | — |
| **길이 ≥ 14** | 글자 획 | 글자 획 (165.91, 648.26)→(165.91, 653.36) 길이 5.1 / BOM 가로선 (113.1, 161.2)→(291.7, 161.2) 길이 178.6 |

- 방향만으로는 부족: case_0001 가로 2,468 + 세로 2,635개 대부분이 글자 획
- 표 선은 칸마다 끊기지 않고 표 끝에서 끝까지 한 번에 그어짐 (case_0001 BOM: 가로선 전부 413.9, 세로선 전부 138.9)
- 테스트 도면은 길이 기준을 넘는 선도 수천 개 (부품 그림·치수선) → 길이는 1차 체, 확정은 3절

**길이 기준 14.** 처음엔 19였으나 상위 1개짜리 모부품 박스 세로변(18.4)이 지워져 BOM 고르기 41개 실패 → 14로 낮춤. 글자 획은 남아도 뒤에서 걸러지지만 표 선은 지우면 되살릴 수 없다 (재현율 우선). 길이 분포·후보 비교: [트러블슈팅 03](../트러블슈팅/03_상위박스_세로변이_지워짐.md)
- 남은 획이 BOM 선에 닿으면 BOM 묶음에 섞일 수 있다 → 칸 나누기는 표 전체를 가로지르는 선만 경계로 쓴다 (취소선과 같은 문제)
- 변수는 도면 크기가 아니라 **글자 크기**. 글자가 훨씬 큰 도면이 나오면 도면마다 글자 크기를 재서 기준을 정한다

**방향 기준 3°.** 테스트 도면(엔지니어 도면)은 선이 살짝 기운다 (88361 연결선 1.1°). "좌표 차이 0.5 이하" 대신 "기울기 3° 이하"를 가로·세로로 본다. 샘플 선은 0° 아니면 5° 이상이라 영향 없음. [트러블슈팅 05](../트러블슈팅/05_기울어진_연결선.md)

## 1-2. 테두리 선 지우기 (2026-11-17)
**문제.** 테두리는 사각형 2~3겹 (case_0001: 페이지 가장자리 y 0 / 바깥 28.4 / 안쪽 42.5). 표제란·리비전 기록란이 안쪽 테두리에 닿아 있어 묶으면 한 덩어리가 된다 (case_0100 리비전 기록란 세로선이 안쪽 테두리 y 70.9에서 시작).

| 후보 | 결과 |
|---|---|
| 페이지 크기 대비 % | ✗ 페이지 ≠ 도면 크기 (case_0500 페이지 폭 12500.8, 맨 바깥 선 0→3370.4). 안쪽 테두리 89.9%로 90% 기준 통과 |
| 닫힌 사각형이면 지움 | ✗ 안쪽 테두리는 표제란 자리에서 끊겨 닫히지 않음 |
| 다른 묶음을 전부 품는 묶음째 버림 | ✗ 가장자리가 덜 그려진 도면(case_0100)은 못 찾음. **BOM이 테두리에 붙은 도면(case_0555·0707·0724)은 BOM까지 버려짐** |
| 긴 선(도면 대비 50%↑)만 지움 | ✗ 세로로 긴 BOM(88500)의 세로선까지 지워짐 |
| **길다 + 가장자리** | ✓ |

**결정.** 묶기 **전에** 테두리 선을 지운다. 테두리 선 = 둘 다 만족:
- 가로선은 도면 폭의 **50% 이상**, 세로선은 도면 높이의 **50% 이상**
- 도면 바깥 경계(후보 선 전체의 최소·최대 x·y)에서 **6% 안쪽**

결과: 샘플 820개·테스트 6개에서 전체를 덮는 묶음 0개, 도면당 14~24개(88500 36개) 지움. 88500 상위 표(선 81)·하위 BOM(선 72)은 따로 온전히 남음. 표제란·리비전 기록란도 각자 묶음으로 남는다.
- 구현 때 확인: case_0475 (BOM 확인 검사에 안 걸림, 그림으로 확인)
- **알려진 한계:** 테두리에 붙은 표의 변은 테두리와 함께 지워진다. case_0001 리비전 기록란 세로선 3개(x 1119.7·1133.9·1148.0, y 42.5→477.6, 길이 435.1)도 50%·6% 조건을 만족해 지워짐. BOM이 아니라 지금은 영향 없음. 리비전 기록란을 읽게 되면 다시 본다

## 2. 격자로 묶기
- 같은 표의 선끼리는 **한 선의 끝점이 다른 선 위에 놓인다** (모서리·T자). case_0001: 세로선 x=432.3의 끝점 (432.3, 171.5)가 가로선 y=171.5 위
- **맞닿음:** 끝점이 다른 선 위 (허용 오차 0.5). 샘플에서 닿는 끝점은 거리가 정확히 0 (case_0001 110개, case_0500 105개)
- **묶음:** 이웃의 이웃도 같은 묶음 = **연결 요소**, 너비 우선 탐색(BFS)으로 찾는다
- 상위(모부품 박스)와 하위 BOM은 연결선으로 닿아서 **한 묶음** (case_0001: 박스 x 564.1~693.1, 연결선 y 108.4·126.8·145.3 → BOM x 398.3~812.2)
- 후보: BOM(+상위), 표제란, 리비전 기록란, 기타 도형

**구현 결과 (case_0001, 2026-11-18, 길이 기준 19일 때).** 선 7,106 → 후보 135 → 테두리 뺀 뒤 121 → 묶음 22 (기준 14에선 후보 150, 묶음 33. 늘어난 건 짧은 선의 작은 묶음)

| 묶음 | 범위 | 정체 |
|---|---|---|
| 0 (선 37) | x 212.6~1162.2, y 42.5~813.5 | 리비전 기록란 + 표제란 + 아래 띠 (서로 맞닿음) |
| 1 (선 31) | x 398.3~812.2, y 99.2~310.4 | **BOM 표 + 모부품 박스 3칸 + 연결선** |
| 2 (선 11) | x 116.2~294.8, y 195.2~310.0 | TOP VIEW 부품 외곽선 |
| 나머지 | | FRONT·RIGHT VIEW 부품 그림, 치수선 |

- 이 단계는 "닿았나"만 본다. 무엇이 표인지는 모른다 → 3절에서 고른다
- 표제란·리비전 기록란은 테두리를 먼저 지워서 테두리와 분리된 채 자기 묶음으로 남음
- **취소선도 BOM 묶음에 들어간다** (표 폭 전체를 가로지르는 가로선이라 ① 통과, 표 테두리에 닿음) → 칸 나누기에서 행 경계와 구분해야 함 ([06](06_취소선.md))

## 3. BOM 표 고르기

| 후보 | 장점 | 단점 |
|---|---|---|
| 헤더 글자 (NO, PART NO …) | 직관적 | 아래 순환 의존 때문에 처음엔 불가능 |
| **모부품 박스 연결선** | 글자 없이 선 모양만으로 가능 | 연결선 모양이 도면마다 같아야 함 (구현 때 확인) |

**순환 의존**
```
BOM 표 찾기 ──필요──▶ 헤더 읽기 ──필요──▶ 모델
     ▲                                   │
     └──────────필요──── 학습 카드 ◀──필요─┘
```
- 연결선 = 박스 오른쪽 끝에서 **수평** → 꺾여 **수직** → 표 맨 위에 화살표. 모두 "수평/수직 + 끝점 맞닿음"이라 글자 없이 찾을 수 있다 → 순환이 끊긴다

**결정.** 연결선이 닿는 표 = BOM. 닿지 않으면 BOM 아님 (리비전 기록란, 표제란 모두 제외). 헤더 글자는 모델이 생긴 뒤 검증용으로만 쓸 수 있다.

**갱신 (2026-11-17): OCR을 쓰면 순환이 사라진다.** 기성 OCR은 학습 없이 처음부터 읽으므로 머리글을 쓸 수 있다 ([02](02_PDF구조와_OCR.md) 문제 3).

| 후보 | 장점 | 단점 |
|---|---|---|
| 선만 | 글자 무관, 크기 무관, 빠름 | 표제란·리비전 기록란도 같은 격자 → 연결선으로 간접 판단 |
| OCR 글자만 | BOM인지 바로 앎 | 범위·행·열은 결국 선이 필요. 큰 도면 전체 OCR은 글자가 뭉개짐. 처음 보는 표기는 못 찾음 |
| **선으로 후보 → 머리글만 OCR → 연결선으로 확인** | 둘이 서로 검증. 판단이 다르면 경고 | 단계 하나 추가 |

**결정.** 섞는다. 범위·행·열은 선, "이게 BOM인가"는 머리글 OCR + 연결선.

### 3-1. 연결선으로 고르기: 구현 규칙 (2026-11-18)
OCR 전이라 연결선만으로 먼저 고른다. case_0001에서 BOM 묶음(주황)과 표제란·리비전 기록란 묶음(파랑)은 둘 다 격자다. 차이는 **격자 위로 연결선이 꽂히는가**다.

| 후보 | 샘플 820개 결과 | 문제 |
|---|---|---|
| 윗변에 아래 끝이 닿는 세로선이 있는 묶음 | ✗ 묶음 여러 개 걸림 | 부품 그림도 해당 |
| + 꽉 찬 가로·세로선 각 3개 이상 | 802/820 | 상위가 많으면(case_0107, 8개) 박스 세로선이 BOM 세로선보다 길어 "꽉 찬 세로선"이 2개뿐 |
| + 꽉 찬 가로선 3개 이상만 | BOM은 모두 포함, 그러나 271개에서 凸 모양 부품(case_0101 x 1619.6~2094.9)도 걸림 | 위 상자 세로변이 아래 상자 윗변에 닿아 연결선처럼 보임. 상위 1개면 연결선 수도 같아 못 가름 |
| **연결선 수 = 모부품 박스 행 수** | **820/820** (길이 기준 14 또는 16·18) | 길이 19에선 779 (1절) |

**결정.** 아래를 모두 만족하는 묶음 = BOM
1. **표 윗변:** 묶음에서 가장 긴 가로선과 길이가 같은 선(꽉 찬 가로선)이 3개 이상, 그중 맨 위 선
2. **연결선:** 아래 끝점이 윗변 위(또는 윗변보다 6 이내 위, 화살표 틈)에 있고 몸통은 윗변보다 위인 세로선 → 위 끝에서 꺾이는 가로선 → 그 출발점이 모부품 박스 세로변의 **칸 중간**(꼭짓점 아님). 틈을 봐주는 건 leg·박스 세로변까지 모양이 다 갖춰질 때만이라 다른 선이 섞이지 않는다 ([트러블슈팅 08](../트러블슈팅/08_상위가_표인_도면.md))
3. **박스 행:** 그 세로변에 닿는 박스 가로선(세로변 안쪽으로 뻗은 것, 연결선 가로 부분 제외)으로 행 경계를 구하고, 연결선마다 출발한 행 번호를 정한다
4. **행마다 연결선 1개.** 연결선이 없는 행은 맨 위 행(머리글, 88500 상위 표)만 허용 (case_0001: 연결선 3, 박스 행 3 = json `num_parents` 3)

- 예 (case_0001): 박스 세로변 x 693.1 (y 99.2→154.5, 박스 가로선 y 99.2·117.6·136.0·154.5 → 3행) / 연결선 y 108.4→x 798.0, y 126.8→x 769.6, y 145.3→x 741.3 → BOM 윗변 y 171.5
- 연결선이 닿는 x는 수량 열의 가운데 (열 경계 727.1·755.5·783.8·812.2) → 4절 매핑에 그대로 쓴다
- 선이 기울 수 있으므로 "세로선의 x", "가로선의 y"처럼 한 좌표로 대표하지 않고, **선의 위 끝·아래 끝 점이 다른 선 위에 있는지**(`point_on_line`)로 확인한다 ([트러블슈팅 05](../트러블슈팅/05_기울어진_연결선.md))
- 테스트 도면 (2026-11-18): 처음엔 22000·88300만 성공. 화살촉 합치기(0절) + 3° + 끝점 확인으로 상위가 박스인 5개 모두 성공 (scratchpad 확인). 88500은 상위가 박스가 아니라 표 전체 → 따로
- 머리글 전체 일치가 아니라 **핵심 단어 조합**: 품번 계열(`PART NO`, `P/NO`) + 수량 계열(`Q'TY`, `QTY`) → 하위 BOM. 열이 추가돼도(MATERIAL, NOTE) 영향 없음
- 품번 단어 하나만 보면 안 된다: 표제란(`MATERIAL / P/NAME / P/NO`, 88361·88400), 상위 표(`PART NO … NOTE`, 88500)에도 있음 → 수량 계열이 없으면 BOM 아님. 상위 표는 버리지 않고 연결선으로 "상위"로 판정
- 같은 뜻 다른 표기는 이름 사전으로 묶고, 사전에 없으면 경고

## 4. 모부품 ↔ 수량 열 매핑
- 화살표가 표 위의 **어느 x 위치**에 닿는지 → 그 모부품의 수량 열
- "맨 아래 박스 = 맨 왼쪽 열" 같은 패턴보다 도면이 직접 알려 주는 연결이 더 믿을 만하다
- 수량 머리글이 여러 열을 덮는 한 칸일 수 있다 (88500: 화살표 끝 y 740.7은 "QTY" 머리글 위, 열 경계선은 머리글 아래 y 771.9부터). 화살표 x를 **머리글 아래의 열 경계**에 대어 열을 정한다
- 상위가 표인 경우와 끝점 추적 규칙은 [13](13_모부품_박스.md)

## 5. 헤더 양식 3종
| header_style | 개수 | 예시 | 특징 |
|---|---|---|---|
| standard | 418 | case_0002 | - |
| slash_pno | 216 | case_0001 | 사선 선 없음 |
| slash_qty_assy | 186 | case_0003 | 수량 열 헤더를 가로지르는 사선 (727.1, 670.4) → (812.1, 650.6) |

- ASSY = Assembly(조립품). 수량 열 헤더는 "어느 ASSY에 몇 개(QTY)"

**결정.** 별도 처리 불필요
1. 헤더 글자는 읽지 않는다
2. 사선은 수평도 수직도 아니라서 1단계 필터에서 빠진다
3. 남아도 헤더 칸 안이라 읽을 칸에 영향 없음
- 구현 때 사선이 격자 묶기에 끼어드는지만 확인
- **갱신 (2026-11-17):** 열 구성이 도면마다 다르다 (88500 하위 표에 MATERIAL 추가). "4번째 칸 = 수량"처럼 순서로 정하면 깨지므로, 이제는 머리글을 OCR로 읽어 **이름으로 열 역할을 정한다**. 수량 열은 화살표가 닿는 열(선). 사선 머리글을 OCR이 읽는지는 구현 때 확인

## 6. 표 종류 분류기 (ML)
**문제.** 선으로 찾은 격자 후보는 하위 BOM, 상위 표, 상위 박스, 표제란, 리비전 기록란이 섞여 있고, 엔지니어마다 다른 종류의 표가 더 나올 수 있다. 규칙(if-else)은 새 종류마다 코드를 고쳐야 한다.

| 후보 | 장점 | 단점 |
|---|---|---|
| 규칙 | 단순, 설명 쉬움 | 새 종류마다 if 추가 |
| **분류기** | 새 종류는 라벨 붙인 예시를 추가해 재학습 | 라벨 필요 |

**결정.** 규칙으로 먼저 만들고, 패턴을 모으며 규칙이 틀린 사례로 분류기를 학습해 비교한다.
- 입력 특징: 행·열 수, 가로세로 비율, 페이지 안 위치, 머리글 단어(OCR), 연결선(화살표가 닿음 / 선이 출발함), 글자 방향
  - 예: 88500 하위 BOM 38행 × 30열(앞 5 + 수량 25), 상위 표 25행 × 4열
- 라벨: 하위 BOM·상위 품번은 json으로 자동. 표제란·리비전 기록란은 수작업 (도면당 후보가 적음)
- 처음 보는 표: "기타" 클래스 + 1등 확률이 낮으면 경고 → 모아서 재학습
- 모델은 작은 선형/트리 계열 (sklearn)

## 전체
```
선 수천 개
  → [화살촉 → 선 끝을 꼭짓점까지]     연결선이 표 윗변에 닿게 (테스트 도면)
  → [수평/수직 + 길이 ≥ 14]           글자·도형 선 제거
  → [50%↑ 길고 + 가장자리 6% 안]      테두리 선 제거
  → [끝점이 맞닿은 묶음 (BFS)]        표 후보들
  → [머리글 OCR + 연결선]            표 종류 (하위 BOM / 상위 / 그 외)
  → [화살표가 닿는 x 위치]           모부품 ↔ 수량 열
  → [격자 선 좌표]                   셀(칸) 위치
  → [머리글 이름]                    열 역할 (품번·품명·수량·기타)
```
범위·행·열은 기하 규칙, 표 종류와 열 역할은 머리글 OCR로 보강한다. 종류가 늘면 분류기(6절).
