# 14. 평가

## 문제
다 만든 뒤 "써도 되나?"와 "어디가 약한가?"를 숫자로 답해야 한다.

| 정할 것 | 결정 |
|---|---|
| 무엇 단위로 세나 | 아래 1 |
| 어느 데이터로 재나 | test PDF, 마지막에 한 번 ([09](../보류_글자학습/09_모델_선택.md)) |
| 출력과 정답을 어떻게 짝짓나 | 아래 2 |
| 틀린 원인을 어떻게 가르나 | 아래 3 |

## 1. 점수 단위
**문제.** 단위가 커질수록 점수가 내려간다 (곱의 법칙).
| 글자 수 | 계산 | 칸이 통째로 맞을 확률 |
|---|---|---|
| 1 | 0.99 | 99% |
| 2 | 0.99 × 0.99 | 98% |
| 12 (품번) | 0.99¹² | **약 89%** |
- 글자 정확도 ≠ 칸 정확도. 행은 여러 칸이 모두 맞아야 하므로 더 낮다

**결정.** 세 단위를 모두 재되 역할을 나눈다
| 단위 | 역할 |
|---|---|
| **행 정확도** | **주 점수.** 사용자가 실제로 쓰는 단위 |
| 칸 정확도 (품번/품명/수량별) | 어느 칸이 약한지 |
| 글자 정확도 | 모델 자체 성능 |

## 2. 행 짝짓기
**문제.** 순서대로 짝지으면 행 하나만 놓쳐도 뒤가 전부 밀려 틀린 걸로 나온다.
```
정답          출력 (2행 놓침)
1 88100-A     1 88100-A   ✓
2 88200-B     3 88300-C   ✗  ← 사실 맞게 읽음
3 88300-C     4 88400-D   ✗
```
**결정.** no로 짝짓는다
- json 1000개에서 한 도면 안에 no가 겹치는 경우 0건 (part_no도 0건)

**함정.** no도 모델이 읽은 값이다
```
정답 13 → 출력 18 (오독)
  → 13은 "빠진 행", 18은 "생긴 행" → 오독 1개가 행 누락처럼 보이고 오류 2개로 셈
```
- 행 점수는 어차피 틀림 (no 칸이 틀림). 문제는 **원인 진단**
- 대응: no로 못 짝지은 행끼리 **품번이나 행 순서로 2차 짝짓기** → 맞으면 "글자 오류", 끝까지 안 맞으면 "행 누락/추가"

## 3. 원인 가르기
**결정.** 위 단계부터 차례로 정답 json과 비교
| 단계 | 비교 | 판정 |
|---|---|---|
| 표 찾기 | 행 수 vs `table_rows` 개수, 수량 열 수 vs `num_parents` | 다르면 표 찾기·칸 나누기 |
| 글자 나누기 | 칸의 묶음 수 vs 정답 글자 수 | 다르면 나누기 |
| 모델 | 개수는 같은데 글자 내용이 다름 | 모델 (`88100`→`88180`은 개수로 못 잡음) |
- 앞 단계 실수는 뒤로 번지므로, 앞 단계가 틀렸으면 뒤 단계 탓으로 세지 않는다
- 틀린 행마다 "표 / 나누기 / 모델" 꼬리표 → 단계별 개수로 고칠 곳의 우선순위
- header_style별, 페이지 크기별, 칸 종류별로 쪼개 보기

## 4. 자동 라벨링과의 차이
정답 출처(json)는 같지만 쓰는 방식이 다르다.
| | 자동 라벨링 (학습) | 평가 |
|---|---|---|
| 대상 | train PDF | test PDF |
| json 사용 | 칸 정답을 글자별로 쪼개 카드 뒷면에 | 최종 출력(행/칸)과 통째로 비교 |
| 개수 안 맞으면 | 칸을 **버림** | **틀린 걸로 셈** |
- 평가에서 버리면 어려운 칸을 빼고 채점해 점수가 부풀려진다. 실제 사용에선 못 버린다
- 글자 정확도(진단용)만 test에서 자동 라벨링 카드로 잰다. 주 점수(행)는 출력과 json을 직접 비교

## 5. 칸 신뢰도 (ML)
**문제.** 위 점수는 정답이 있을 때의 **전체 성적**이다. 실제 도면엔 정답이 없어서, 결과를 받은 사람은 어느 칸을 믿어도 되는지 모른다. 정확도 100%는 불가능하므로 "어디를 다시 봐야 하나"가 필요하다.

| | 평가 점수 (1~4절) | 칸 신뢰도 |
|---|---|---|
| 언제 | 개발 중, 정답 있음 | 실제 사용, 정답 없음 |
| 방법 | json과 비교 | 예측 |
| 결과 | "칸 정확도 95%" | "이 칸은 틀렸을 확률 0.81" (칸마다) |

**결정.** 칸마다 "틀렸을 확률"을 예측하는 로지스틱 회귀. 기준보다 높으면 검수 표시.
```
학습: 샘플 PDF → 파이프라인 → 칸마다 OCR 결과 + 특징
      json과 비교 → 라벨 맞음(0)/틀림(1) → 학습
사용: 실제 PDF → 칸마다 특징 → 틀렸을 확률 → 기준 초과면 [검수]
```
**특징 (서로 맞아야 하는 정보가 어긋나는지)**
| 특징 | 88500 실제 | 의심 상황 |
|---|---|---|
| OCR 자신감 | (엔진이 주는 1등 후보 점수, 0~1) | 낮음 (예: 0/O가 비슷한 점수) |
| 품번 형식 | `88101-NX560` 꼴 | 형식에 안 맞음 |
| 같은 표 품번 뒷부분 | 1~14행 `-NX560`, 15~23행 `-NX540` | 한 칸만 다름 |
| 중복 | 도면 안 품번·no 중복 0건 (json 1000개) | 같은 값이 두 번 |
| no 순서 | 1, …, 18, 18-1, 19, … 38 | 건너뛰거나 거꾸로 |
| 수량 값 | `1`, `4`, `-` | `l`, `I` 같은 값 |
| 열 값 사전 | MATERIAL `ASSY`, `SCM435MS`, `SWCH10A` | 처음 보는 단어 |
| 상위 ↔ 하위 옵션 | 88500-NR520 = 88101-NX560 `(8WP+2_L/SUPT+HTR+USB2)` | 연결된 두 칸 옵션이 다름 |
| 표제란 | 상위 품번 목록이 `P/NO` 칸에도 (88361, 88400) | 둘이 다름 |
| 지운 선 | 칸에 취소선·삼각형이 있었음 | 두 줄 칸 등 어려운 칸 |

- 라벨은 json 비교로 자동 생성. 분할은 PDF 단위 ([09](../보류_글자학습/09_모델_선택.md))
- **표시**: xlsx에서 해당 칸 색칠 + 검수 열에 이유·점수, 별도 시트에 검수 목록
- **기준값**: val에서 정한다. 낮추면 놓치는 오류는 줄고 검수량은 늘어난다 (정밀도·재현율 트레이드오프)
- **보정 확인**: "0.8 근처 점수 칸 100개 중 실제로 약 80개가 틀렸나"를 val에서 확인해야 점수를 믿을 수 있다
