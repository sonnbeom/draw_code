# 18. 연결 추적: 상위 박스 행 → 수량 열 (3단계)

> 앞 단계: [03](03_표_찾기.md) 3-1절 BOM 고르기(연결선 찾기), [17](17_칸_나누기.md) 칸 나누기. 상위가 표인 경우(88500)는 [13](13_모부품_박스.md), 3-B로 따로.

## 문제 정의
- OCR은 글자와 위치만 준다. 수량 칸의 "1"이 **어느 상위 품번의 수량인지**는 연결선을 따라가야 안다
- 연결선(`Connector`: leg·drop·box_side)과 열 경계(`BomGrid.col_xs`)는 이미 있다 → 새 선을 찾을 필요 없이 **점이 어느 칸에 들어가는지**만 판정하면 된다

## 방법
1. leg 출발점 y가 박스 행 경계 y 중 어느 두 값 사이인지 → **박스 행 번호** (0 = 맨 위)
2. drop 아래 끝 x가 `col_xs` 중 어느 두 값 사이인지 → **열 번호**
3. 짝 목록 `ParentLink(connector, box_row, col)`

1과 2는 같은 계산(값이 몇 번째 구간에 있나)이라 함수 하나 `find_slot(value, bounds)`로 쓴다. 경계 위에 딱 걸리면 None.

case_0001 실측:

| leg 출발 y | 박스 행 (경계 99.2 / 117.6 / 136.0 / 154.5) | drop 아래 끝 x | 열 (QT'Y 727.1 / 755.5 / 783.8 / 812.2) |
|---|---|---|---|
| 108.4 | 0 (맨 위) | 798.0 | 5 (맨 오른쪽) |
| 126.8 | 1 | 769.6 | 4 |
| 145.3 | 2 | 741.3 | 3 |

## 정한 것
| 문제 | 후보 | 결정 |
|---|---|---|
| leg 출발점 | A. `find_connectors`가 이미 구한 값을 `Connector`에 저장 / B. 3단계에서 다시 계산 | **A.** 같은 계산을 두 번 하지 않음 |
| 박스 행 경계 | A. `count_box_rows` 안의 계산을 `box_row_ys`로 빼서 같이 씀 / B. 새로 작성 | **A.** 행 수 = `len(box_row_ys) - 1`로 같은 근거 |
| 열 번호 | A. 표 전체 열 번호 (`Cell.col`과 같음) / B. 수량 열 안에서 몇 번째 | **A.** 6단계 조립에서 OCR 글자를 `Cell`에 배정할 때 같은 번호로 맞춤. 수량 열 안 순서는 머리글 QT'Y 칸의 `col`을 빼면 나옴 |

## 확인 기준
품번까지 맞는지(박스 0행이 정말 어느 품번인지)는 OCR이 필요하므로 6단계에서 json `parents_order_left_to_right`와 비교한다. 3단계는 선 좌표만으로 확인한다.

| 검사 | 틀린 예 |
|---|---|
| 짝 수 = json `num_parents` | 연결선 하나를 못 따라감 |
| 박스 행이 서로 다름 (박스별) | 두 연결선이 같은 행에서 나옴 |
| 열이 서로 다르고, 전부 머리글 QT'Y 병합 칸 안, 병합 칸 폭 = 짝 수 | 두 연결선이 같은 열에 떨어짐, 품명 열·표 밖에 떨어짐 |
| (세기만) 방향 | — |
