# 06. 취소선 [DEL]

## 문제
취소선이 행의 글자를 전부 이어 버려서 "이어진 선끼리 묶기"를 하면 하나의 묶음이 된다. DEL 행도 품번·품명·수량을 **다 읽어야 한다.**

| 후보 | 장점 | 단점 |
|---|---|---|
| DEL 행은 건너뜀 | 단순 | 행 정보를 잃음 → 불가 |
| **취소선을 찾아 기록 후 제거** | 행을 그대로 읽을 수 있음 | 테두리선과 구분 필요 |

## 결정. 찾아서 기록하고 지운다
```
① 취소선 발견 → "13번 행 = DEL" 기록
② 취소선을 선 목록에서 제거
③ 남은 선으로 글자 묶기
```
- 선 좌표 방식이라 가능: 선이 따로따로 저장된 목록이라 하나만 빼면 된다 (이미지라면 겹친 픽셀이 섞임)
- 구분 기준: 취소선은 **행의 한가운데**에 있고 **글자 선이 가로지른다.** 테두리선은 행의 경계에 있다
- 취소선도 "길고 수평"이라서 표 선 후보 단계에서 잡힌다 → 격자를 만들 때부터 골라낸다
- 역할 분담: DEL 판단은 **기하 규칙**, 글자 읽기는 **머신러닝**

## 취소선 모양: 샘플과 실제 도면이 다르다 (2026-11-20 확인)
| | 모양 | 칸 나누기에서 |
|---|---|---|
| 샘플 (프로그램 생성) | 표 폭 전체를 가로지름 | 꽉 찬 가로선이라 행 경계 후보에 섞임 → "글자 획이 가로지름"으로 뺌 ([17](17_칸_나누기.md)) |
| 실제 도면 (엔지니어) | **글자 위에만** 짧게 (22000 15·19행, 28440 3행, 88500 수량 칸) | 꽉 찬 가로선이 아니라 처음부터 후보가 아님 |

- 판정 함수 `is_struck`(선 + 글자 획 → 가로지르나)는 여러 글자를 가로지르는 긴 취소선(품번·품명 칸)에 쓴다. 한 글자짜리(수량 칸)는 아래 "짧은 취소선" 방식

## 무엇을 기록하나 (4-1, 2026-11-23)
실제 도면에서 확인한 것 (88500):
- 취소선은 **글자마다 따로** 긋는다. 하위 I/NO 12: PART NO 106.3 · PART NAME 175.0·229.8 (두 줄) · MATERIAL 40.6. 폭 전체 선은 0개
- **취소 + 새 글자**: 상위 I/NO 7·19는 한 칸에 옛 품번(취소)과 새 품번(파랑)이 위아래로 있음 → 칸 단위가 아니라 **줄 단위**로 취소 여부가 필요
- 상위가 취소되면 연결된 수량 열도 보통 취소: 상위 I/NO 12 → 12열 6칸, I/NO 22 → 23열 6칸
- 예외: 상위 I/NO 6(`88500-NR050`)은 취소인데 6열 수량엔 취소선 없음 (현업: 하위까지 다 지우기 버거운 경우가 있음)

| 후보 | 판단 |
|---|---|
| 상위 취소면 연결된 수량도 취소로 추론해 출력 | ✗ 6열처럼 그려진 것과 달라짐 |
| **그려진 대로 기록 + 상위 취소는 따로 표기** | ✓ 현업 요구: 상위 삭제 표기 + 하위 값은 보여줌 |

결정:
- 수량 칸 값은 그려진 대로, 그 칸에 취소선이 있으면 "취소" 표기
- 상위 품번이 취소면 "상위 삭제" 표기 (수량 열에 그대로 이어짐)
- 행·상위 취소로 추론한 것과 실제 취소선이 다르면 검수 표시 (88500 6열)

## 상위 삭제 vs 상위 교체 (4-1 ④, 2026-11-24)
테스트 6개 상위 쪽 취소선 (긴 취소선 `is_struck`):

| 도면 | 상위 | 모양 |
|---|---|---|
| 88361 | 박스 4행 중 위 2행 (`88460-NX540`, `88360-NX540`, 파랑) | 품번에 취소선만 → **삭제** |
| 88500 | 상위 표 I/NO 22, 12, 6 | 행 전체(품번·품명·NOTE)에 취소선 → **삭제** |
| 88500 | 상위 표 I/NO 19, 7 | 옛 품번에만 취소선 + 그 아래 새 품번(파랑) → **교체** |
| 22000·28440·88300·88400 | - | 없음 |

"취소선이 있으면 상위 삭제"로만 하면 I/NO 19·7(교체)도 삭제로 잘못 나온다.

| 후보 | 판단 |
|---|---|
| 새 품번만 상위로 (옛 품번 버림) | ✗ 변경 이력이 사라짐 |
| **새 품번을 상위로 + 옛 품번은 "삭제(변경 전)"로 함께** | ✓ 현업 요구 |

결정:
- 취소된 줄 **바로 아래 같은 칸에 취소 안 된 줄**(새 품번)이 있으면 **교체**: 새 품번 = 상위, 옛 품번 = 삭제 표기로 함께 출력
- 아래에 새 줄이 없으면 **삭제**
- 하위 BOM도 같은 규칙 (22000 3행 품번: 지운 품번 + 새 품번)

## 짧은 취소선 판정: 한 글자 위의 선 (4-1)
**문제**: 수량 칸은 글자 1개라, 취소선과 글자 자신의 가로 획을 구분해야 한다.
- 길이로 못 가름: 취소선 4.2 (88500 하위 I/NO 33·35의 `1`) = `1`의 받침 획 4.2
- `is_struck`만 쓰면 `4`의 가로 막대(세로 획이 관통)도 취소선으로 잡음
- "가운데 높이 가로선 = 취소"도 안 됨: 이 폰트의 `2`는 원래 가운데 높이에 가로 획이 있음

**확인한 사실** (수량 칸 선 모양 묶기):
- 테스트 6개 중 5개에 짧은 취소선: 22000 `2`, 28440 `2`, 88300 `1`, 88361 `1`, 88500 `1` 8칸·`4` 4칸
- 지워진 글자는 전부 **정상 모양 + 가로선 1개** (글자 가운데 높이)
- 같은 폰트라 샘플과 테스트의 글자는 선 구성이 같고 크기만 다름 (`1` 선 3개, `2` 9개, `4` 5개 / 높이 샘플 7, 테스트 9)

| 후보 | 장점 | 단점 |
|---|---|---|
| A. OCR | - | 취소 여부를 주지 않음, 지워진 `1`을 다른 글자로 읽을 수 있음 (추정, 5단계에서 확인) |
| B. 학습 (칸 그림 → 취소?) | - | 짧은 취소 예시가 테스트 12개뿐, 샘플엔 없음 |
| C. 도면 안에서 모양 빈도 → 많은 모양 = 정상 | 사전 불필요 | 그 글자가 도면에 하나뿐(지워진 것)이면 비교 대상 없음 |
| **D. 정상 글자 사전(샘플에서 미리, 높이로 크기 맞춤)과 비교** | 글자가 하나뿐이어도 판정 | 사전 만드는 단계 필요 |

**결정: D.** 칸 모양 = 사전의 어떤 글자 → 정상, 사전 글자 + 가로선 1개 → 취소, 어느 쪽도 아니면 **검수 표시**.
- 학습이 아니라 조회 (Java의 상수 `Map<모양, 글자>`)
- 사전은 **샘플로만** 만든다. 테스트 도면은 ① 지워진 글자(정상 + 가로선)가 섞여 들어갈 수 있고 ② 실제 도면 6개가 유일한 확인 수단이라 사전에 쓰면 확인이 안 됨 (데이터 누수). 테스트에서 검수로 걸린 모양은 그림으로 보고 정상이면 사전에 추가하고 기록
- 구현 때 확인: 좌표 반올림 차이 허용 오차 (88500 `4`가 반올림으로 두 묶음), 한 칸 두 줄 (22000 지워진 `2` + 새 `1`)

**테스트 6개 확인 결과** (표 안, 행 경계가 아닌 길이 12 이상 가로선)
| 칸 | 결과 |
|---|---|
| 품번·품명·재질 (긴 선) | 23개 전부 `is_struck`로 잡힘 (22000 5, 28440 2, 88300 4, 88361 4, 88500 8) |
| I/NO (글자 1~2개) | 22000 행 16 (길이 14.0) 잡힘. **88500 I/NO `22` (15.6) 놓침**: 취소선이 `2`의 가운데 가로 획과 같은 높이(1447.6)라 획이 선에 닿기만 하고 관통하지 않음 |
| 모르던 모양 | 88361 가로선 2개 칸 = **지워진 `-`** (`-` + 취소선, `=`처럼 보임) → 사전 규칙("정상 + 가로선 1개")에 그대로 맞음. 88300 선 12개 칸 = 정상 `3` |

- 취소선 색은 검정·파랑 둘 다 (88361·88300 취소 행은 파랑) → 색은 판정에 안 씀
- I/NO 칸도 한 글자짜리 문제와 같으므로 사전 방식이 필요

**글자 나누기** (사전은 글자 하나 단위라 칸을 글자로 나눠야 함)

| 후보 | 판단 |
|---|---|
| 이어진 선 = 한 글자 | ✗ `1`의 받침이 세로 획과 떨어져 있음. 88500 `22`는 두 `2`가 끝점을 공유해 이어짐 |
| x 범위가 겹치면 한 글자 | ✗ `I`·`N`처럼 끝에 있는 세로 획은 x 폭이 0이라 잘림 (샘플 품번 390칸 전부 틀림). `22`는 뒤 `2`의 세로 획이 앞 `2`의 오른쪽 끝 x 3839.6에 걸쳐 어느 글자인지 모름 |
| 틈(< 0.5)으로 자르기 | 샘플 ✓ (글자 사이 틈 약 1.5, 품번 1983/1983칸 글자 수 = json), 테스트 I/NO `22`·`10`은 틈 0이라 ✗ |
| **사전 글자를 왼쪽부터 끼워 맞추기** | ✓ 붙은 글자도 사전 모양에 맞는 쪽으로 정해짐. 다 맞추고 **남는 가로선 = 취소선**, 아무것도 안 맞으면 검수 |

결정:
- **사전 만들기 (샘플)**: 틈으로 자르기 → 글자 수가 json 문자열과 같은 칸만 써서 글자마다 json 글자를 붙여 저장 (`Map<모양, 글자>`). 크기는 글자 높이로 맞춤
- **도면 읽기 (테스트·실제)**: 줄 나누기 → 사전 글자를 왼쪽부터 끼워 맞추기 → 남는 가로선이 취소선
- 결과적으로 수량·I/NO 칸은 글자도 읽힘 → 5단계에서 OCR과 비교할 거리
