# 구현 로드맵

> 설계는 [15](15_전체_파이프라인.md). 이 문서는 "무엇을 어떤 파일에, 어떤 순서로, 무엇으로 확인하며" 만드는지만 정한다.

## 문제 정의
- 설계(①~⑧ + ML 2개)를 코드로 옮길 순서와 파일 구성을 정해야 한다
- 앞 단계 결과가 뒤 단계 입력이므로, 단계마다 "끝났다"를 확인할 기준이 필요하다

## 현재 코드 (2026-11-18)
| 파일 | 상태 |
|---|---|
| `pyproject.toml` | Python ≥3.12, 의존성 `pymupdf`, `matplotlib` |
| `bom/extract_lines.py` | 1단계 완료: `Line` dataclass, `extract_lines()` (qu→4선) |
| `bom/geometry.py` | 선 기본 계산: `is_horizontal`, `is_vertical`, `length`, `point_on_line`, `touches`, `bbox` → (x_min, x_max, y_min, y_max) |
| `bom/table_candidates.py` | 2단계 앞부분 완료: `filter_candidates` → `remove_frame` → `group_lines` (BFS), `find_table_candidates` |
| `explore/drawing_check.py` | get_drawings 구조 확인 |
| `explore/plot_lines.py` | 1단계 확인 (다시 그린 그림 = 원본) |
| `explore/plot_groups.py` | 2단계 확인 (묶음별 색칠) |

- 파일 나누기 원칙: 파일 하나 = 한 단계 또는 한 종류의 일 (너무 잘게는 X). 빈 `find_table.py`는 지우고 위처럼 나눔
- 겪은 버그: `bbox` 반환 순서가 받는 쪽과 달라 테두리 판정이 전부 참 → 선이 다 지워짐. tuple은 순서로만 풀리므로 docstring에 순서를 적는다

- `.venv` 설치 패키지: pymupdf, numpy만

## 단계
| 단계 | 파일 (제안) | 만들 것 | 끝났다는 확인 | 새 패키지 |
|---|---|---|---|---|
| 1 선 추출 | `bom/extract_lines.py` | PDF 한 쪽 → 선분 목록 `(x1, y1, x2, y2, 색, …)` | matplotlib으로 다시 그린 그림 = 원본 | matplotlib |
| 2 표 + 칸 | `bom/geometry.py`(선 기본 계산, 3·4단계도 씀), `bom/table_candidates.py`(후보·테두리·묶기), `bom/select_bom.py`(BOM 고르기), `bom/split_cells.py`(행·열) | 긴 선 → 맞닿은 묶음 → 격자 → 행·열 경계 | BOM 표만 색칠, 행 수 = json `num_items` | 없음 |
| 3 연결 추적 | `bom/connect.py` | 상위 항목 → 끝점 공유로 추적 → 수량 열 번호 | 88500 25/25, 샘플 수량 열 수 = `num_parents` | 없음 |
| 4 규칙 처리 | `bom/rules.py` | 취소선·삼각형·연결선 찾기 → 기록 후 지움 | DEL·rev가 json과 일치 | 없음 |
| 5 OCR | `bom/ocr.py` | 칸 이미지 → 문자열, 머리글 OCR | 샘플 val 칸 정확도, 혼동 글자 목록 | OCR 엔진 (이때 결정) |
| 6 조립·출력·평가 | `bom/assemble.py`, `bom/evaluate.py` | 행 → xlsx(+검수 표시), json 비교 | test 행 정확도, 단계별 원인 개수 | openpyxl |
| 7 ML 칸 신뢰도 | `bom/confidence.py` | 칸 특징 → 틀렸을 확률 | val 정밀도·재현율, 보정 | scikit-learn |
| 8 ML 표 종류 | `bom/table_type.py` | 격자 후보 → 종류 | 규칙 대비 정확도 | (7과 같음) |
