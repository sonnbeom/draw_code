# 1. PDF 구조와 OCR vs 선 좌표 (Q1~3)

> 출발점: "PDF를 넣으면 xlsx가 나오게" 하려면 무엇부터 알아야 하나?

## Q1. 모델 하나로 통째로 풀 수 있을까?

PDF를 모델 하나에 통째로 넣고 xlsx가 나오게 학습시킬 수 있을까?

**내 답.**
1. PDF 구조를 몰라서 글자를 가져올 수 있을지, OCR을 해야 할지 모르겠다
2. 표 위치는 몰라도 비슷한 표기를 학습하면 찾을 수 있지 않을까
3. 크기가 어디까지 커질지 모른다는 게 문제

**정리.**
- 내가 고민한 세 가지(글자 얻기 / 표 찾기 / 크기 문제)가 곧 **단계 나누기**다. 통째로 풀기보다 단계를 나누는 게 실무 방식이다.
- PDF가 글자를 저장하는 방식은 두 가지다.
  - **텍스트로 저장:** "'88114'를 써라". 복사하면 글자가 나온다.
  - **선으로 저장:** "(100,200)→(105,210) 선을 그어라"의 반복. 우리 PDF는 **전부 이 방식**이다.
- CAD 프로그램은 도면용 **선 글꼴**(SHX 스트로크 폰트)을 쓰고, PDF로 내보내면 글자가 선 그리기 명령으로 바뀐다. 사람이 선을 하나하나 그은 게 아니다. (내가 "만든 사람이 선으로 그은 거냐"고 물어봄)
- **컴퓨터에게는 "이건 8이다"라는 정보가 어디에도 없다.** 좌표 숫자만 있다. → 그래서 머신러닝이 필요하다.

## Q2. 이미지 OCR vs 선 좌표

이미지로 바꿔서 OCR을 할까, 선 좌표를 직접 분석할까?

**내 답.** 위치(타겟)를 먼저 찾을 수 있다면 둘 다 가능하다. 위치 인식이 우선이다. OCR은 변수가 있어서 선 좌표가 나아 보인다.

## Q3. OCR의 변수가 구체적으로 뭘까?

**내 답.** 이미지로 바뀌면 행·열 대응관계가 사라지고, 읽는 순서가 꼬일 수 있다. (해상도는 잘 모르겠다)

**정리.**
- 문제는 **① 찾기(검출) → ② 읽기(인식)** 순서로 나뉜다. 찾기가 틀리면 읽기는 소용없다.
- OCR은 글자만 읽어 줄 뿐, 그 글자가 어느 행·어느 열인지는 따로 알아내야 한다.
- 해상도 문제: case_0306(가로 11,905pt)을 2000px 이미지로 만들면 약 6pt가 1px이 된다. 글자가 1~2픽셀짜리 점이 된다.
- 선 좌표는 확대·축소와 상관없이 원래 값 그대로다. → **선 좌표 방식 선택**
