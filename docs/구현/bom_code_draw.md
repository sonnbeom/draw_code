# BOM 찾기 코드 그림 해설

도면 PDF에서 뽑은 선 목록으로 **BOM 표**와 **모부품 박스 → BOM 연결선**을 찾는 코드를 그림으로 정리한 문서.

- 좌표계: **y가 아래로 갈수록 커진다** (y가 작을수록 위)
- 모든 선은 곧은 선분 `Line(x1, y1, x2, y2)`
- 좌표가 조금씩 어긋나도 되도록 **허용 오차(TOL)**를 곳곳에 둔다

---

## 0. 전체 흐름

```
PDF 선 목록
   │
   ▼
[2단계 앞부분: 표 후보 묶음]  find_table_candidates
   ① filter_candidates   글자 획 제거
   ② remove_frame        도면 테두리 제거
   ③ group_lines         닿는 선끼리 묶기
   ④ 정렬                선 많은 묶음부터
   │
   ▼
[BOM 고르기]
   ① find_top            표인지 판정 + 윗변 찾기
   ② find_connectors     윗변에 닿는 연결선 찾기
   │
   ▼
BomMatch(lines, top, connectors)
```

## 1. 기본 도구 (geometry)

### 1-1. 가로선 / 세로선 판정 — `abs(ln.y1 - ln.y2) <= AXIS_TOL`

시작점과 끝점의 높이 차이가 오차 이하이면 **가로선**으로 본다. (x로 같은 검사를 하면 세로선)

```
(0, 100.0) ────────────── (50, 100.3)   y 차이 0.3 ≤ AXIS_TOL → 가로선 ✅

(0, 100) ─────
              ─────
                   ───── (50, 105)      y 차이 5 > AXIS_TOL  → 가로선 ❌
```

### 1-2. 선 길이 — `length`

가로·세로선만 다루므로 `x 변화량 + y 변화량`이면 충분하다. (제곱근 불필요)

```
가로선  (0,10) ──────────── (50,10)     |50-0| + |10-10| = 50  ✅ 실제 길이와 같음

세로선  (20,0)
          │
          │                              0 + |30-0| = 30        ✅
          │
        (20,30)

대각선  (0,0)
           ╲
             ╲                           30 + 40 = 70           ❌ 실제는 50
               ╲ (30,40)                 → 대각선엔 쓰면 안 됨
```

### 1-3. 점이 선분 위에 있나 — `point_on_line(x, y, ln)`

선분을 오차만큼 **넓힌 얇은 띠** 안에 점이 들어오는지 본다.

```
TOUCH_TOL = 1,  가로선 (0,10) → (50,10)

        x: -1 ~ 51
     ┌──────────────────────┐  y = 9
     │●━━━━━━━━━━━━━━━━━━━━●│  y = 10   ← 선분
     └──────────────────────┘  y = 11

     (25, 10)    → 띠 안   True
     (25, 10.5)  → 띠 안   True
     (50.8, 10)  → 띠 안   True   (끝을 살짝 넘었지만 오차 안)
     (25, 15)    → 띠 밖   False
     (60, 10)    → 띠 밖   False
```

**쓰임: 두 선이 만나는지 확인**

```
세로선의 x = 3, 가로선의 y = 6  →  만난다면 그 점은 (3, 6) 뿐

            │ 세로선 (x=3)
            │
  ──────────●──────────  가로선 (y=6)
            │(3,6)
            │

  point_on_line(3, 6, 가로선)  and  point_on_line(3, 6, 세로선)
  → 둘 다 True면 진짜 교점
```

```
만나지 않는 경우

  ──────────────●           ●  ← 후보점 (80, 10)
  가로선 (x: 0~50)          │
                            │ 세로선 (x=80)

  세로선 위: True / 가로선 위: False (가로선은 x=50에서 끝남) → 교점 아님
```

### 1-4. 두 선이 닿나 — `touches(a, b)`

**한 선의 끝점**이 다른 선 위에 있는지 4번 확인한다.

```
 ㄱ / L 모양 (끝끼리)      T 모양 (끝이 중간에)       + 모양 (가운데끼리)

  ●──────────              ──────●──────                  │
  │                              │                   ─────┼─────
  │                              │                        │

  True ✅                   True ✅                   False ❌
                                                     (교점이 어느 선의 끝점도 아님)
```

`+`를 놓쳐도 보통 표는 테두리를 통해 다 이어진다.

```
┌──────┬──────┐   안쪽 선들은 끝이 테두리에 T자로 닿음
│      │      │   → + 교차를 놓쳐도 전부 한 묶음
├──────┼──────┤
│      │      │
└──────┴──────┘
```

예외: 테두리에 안 닿고 `+`로만 교차하는 선은 떨어져 나간다.

```
┌─────────────┐
│      │      │
│   ───┼───   │   ← 이 가로선은 어디와도 "닿지" 않음
│      │      │
└─────────────┘
```

### 1-5. 선 묶음을 감싸는 네모 — `bbox(lines)`

모든 선의 x, y 중 최소·최대를 구한다. **반환 순서: `(x_min, x_max, y_min, y_max)`**

```
(x_min, y_min)
      ┌─────────────────────────┐
      │   ──────────            │
      │        │                │
      │        │    ─────────   │
      │        │                │
      └─────────────────────────┘
                          (x_max, y_max)
```

> ⚠️ 흔히 떠올리는 `(x_min, y_min, x_max, y_max)` 순서와 다르다. 이 착각으로 버그가 났던 적이 있어서
> 이후 결과물(`BomMatch`)은 튜플 대신 이름 붙은 클래스로 만들었다.

## 2. 표 후보 묶음 찾기 — `find_table_candidates`

### ① 후보 거르기 — `filter_candidates`

**가로 또는 세로 + 길이 19pt 이상**만 남긴다. 글자 획과 대각선이 빠진다.

```
 버림                                  남김
  ╱  ╲   대각선 (사선, 화살표 머리)       ────────────────────  긴 가로선
  ─ │ ┐  짧은 획 (글자 "ㅁ", "E" 등)      │
                                       │  긴 세로선 (≥ 19pt)
                                       │
```

19pt 근거: 글자 획 < 19pt, 표 행 높이 ≈ 19.8pt (가장 짧은 표 선도 통과)

```
├──────────┤
│  볼트    │  ↕ 19.8pt  ← 한 칸짜리 세로선도 19 이상이라 남음
├──────────┤
```

### ② 테두리 지우기 — `remove_frame`

**길고(도면의 50% 이상) + 가장자리에 있는(끝에서 6% 이내)** 선을 뺀다.

```
  ┌══════════════════════════════════════════┐ ← 테두리: 길고 + 가장자리 → 삭제
  ║                                          ║
  ║    ───────────────────────────           ║ ← 길지만 가운데 → 남김
  ║                                          ║
  ║                         ┌──────┬──────┐  ║
  ║                         │      │      │  ║ ← 가장자리 근처지만 짧음 → 남김
  ║                         └──────┴──────┘  ║
  └══════════════════════════════════════════┘

  가로선: 길이 ≥ 0.5 × 폭(w),   위/아래 끝에서 ≤ 0.06 × 높이(h)
  세로선: 길이 ≥ 0.5 × 높이(h), 왼/오른 끝에서 ≤ 0.06 × 폭(w)
```

왜 지우나: 표들이 테두리에 닿아 있으면 ③에서 **모든 표가 테두리를 통해 한 묶음**이 되어버린다.

### ③ 닿는 것끼리 묶기 — `group_lines`

`touches`로 닿는 선을 찾고, **이웃의 이웃까지** 같은 묶음으로 모은다 (BFS).

```
 A ── B ── C        D ── E          F
                                    
 묶음 1: [A, B, C]  묶음 2: [D, E]  묶음 3: [F]
 (A와 C는 직접 안 닿아도 B를 통해 연결)
```

### ④ 정렬

선이 많은 묶음부터. 진짜 표는 선이 많아서 앞쪽에 온다.

```
 groups = [ [표 선 40개], [그림 선 6개], [밑줄 1개] ]
             ↑ 가장 유력한 표
```

## 3. BOM 고르기

### 결과 그릇 — `BomMatch`

```
   [박스 A]──┐        [박스 B]──┐        ← connectors 2개 = 상위 품번 2개
             │                  │
     ┌───────▼──────────────────▼──────┐ ← top (BOM 윗변)
     │            BOM 표               │
     └─────────────────────────────────┘
     ↑ 박스 + 연결선 + BOM 표 전체 = lines
```

| 필드 | 뜻 |
|---|---|
| `lines` | 묶음 전체 선 (BOM + 박스 + 연결선) |
| `top` | BOM 윗변 |
| `connectors` | 연결선 목록 |

### 연결선 하나 — `Connector`

```
┌──────────┐
│ 모부품   │ ← box_side (박스의 세로변)
│  박스    ├──────────────┐ ← 꺾이는 점
└──────────┘     leg      │
                          │ drop
                          │
        ┌─────────┬───────▼───┬────────┐ ← BOM 윗변
        │ 품명    │   수량    │  ...   │
        ├─────────┼───────────┼────────┤
                       ↑
              drop의 x = 수량 열 가운데 (3단계에서 씀)
```

| 필드 | 뜻 |
|---|---|
| `box_side` | 출발한 모부품 박스의 세로변 |
| `leg` | 가로 부분: 박스 세로변 → 꺾이는 점 |
| `drop` | 세로 부분: 꺾이는 점 → BOM 윗변 |

---

### ① 표 윗변 찾기 — `find_top`

가장 긴 가로선과 길이가 거의 같은 **꽉 찬 가로선**이 3개 이상이면 표. 그중 **맨 위(y 최소)**가 윗변.

```
   ─────────           ← 짧음 (박스/연결선) → 꽉 찬 선 아님

┌──────────────┐  ← 꽉 찬 선 ①  y 최소 → top ✅
│  품명 │ 수량 │
├──────────────┤  ← 꽉 찬 선 ②
│  볼트 │  4   │
├──────────────┤  ← 꽉 찬 선 ③
│  너트 │  4   │
└──────────────┘  ← 꽉 찬 선 ④

꽉 찬 선 = 길이 ≥ (가장 긴 길이 − FULL_LEN_TOL)
```

꽉 찬 선 개수로 판정:

```
 1개  ──────────            그냥 긴 선           → None
 2개  ┌────────┐            박스일 수도 있음      → None
      └────────┘
 3개+ ┌────────┐
      ├────────┤            행이 2칸 이상 → 표    → 맨 위 선 반환
      └────────┘
```

---

### ② 연결선 찾기 — `find_connectors`

윗변에서 시작해 **아래 → 위로 거슬러 올라가며** 3단계 확인. 하나라도 실패하면 버린다.

```
     ┌───────┐
     │ 박스  ●───────────┐   ③ leg 반대쪽 끝에서 박스 세로변 찾기   (_find_box_side)
     │       │   leg     │   ② drop 위 끝에서 꺾인 가로선 찾기      (_find_leg)
     └───────┘           │
                         │ drop
                         │   ① 윗변에 아래 끝이 닿는 세로선 찾기
        ┌────────────────▼────────┐  ← top
        │        BOM 표           │
```

#### 단계 ①: 위에서 내려와 윗변에 닿는 세로선인가

```
 lands_on_top : 아래 끝이 윗변 높이 + 윗변 x범위 안
 above_top    : 위 끝이 윗변보다 확실히 위

         │  ← 연결선: 위에서 내려와 닿음           통과 ✅
         │
    ─────┴─────┬─────────── top
               │  ← 표 안쪽 세로선: 아래로 뻗음      탈락 ❌
               │

                          │
                          │  ← 같은 높이지만 표 밖   탈락 ❌ (x범위 밖)
    ───────────────── top ┘
```

#### 단계 ②: 위 끝에서 꺾여 나가는 가로선 — `_find_leg`

같은 높이(y ≈ y_up)에 있고, **끝(x1 또는 x2)**이 꺾이는 점에 닿는 가로선.

```
 박스가 왼쪽                 박스가 오른쪽

 ──────────●                 ●──────────
     leg   │ (x2가 닿음)      │   leg     (x1이 닿음)
           │ drop            │ drop
```

출발점 = 꺾이는 점의 **반대쪽 끝**

```
 start_x = leg.x1 if (leg.x2가 꺾이는 점) else leg.x2

  start_x                꺾이는 점
     ●━━━━━━━━━━━━━━━━━━━━━━●
     ↑ 여기서 박스를 찾음     │
```

#### 단계 ③: 출발점을 **중간에** 품는 세로선 — `_find_box_side`

```
 범위를 오차만큼 "좁혀서" 끝 근처는 제외

  side_up  ─┬─   ← 여기 근처는 제외
            │
            ●──── leg    ← 중간에 T자로 꽂힘 → 박스 세로변 ✅
            │
  side_down ─┴─  ← 여기 근처도 제외
```

왜 끝을 제외하나: 끝에서 만나는 `ㄱ`자는 **도형의 모서리**일 가능성이 크다 (凸 모양 부품 등).

```
        ┌───┐
        │   │
    ┌───┘   └───┐   ← 세로선 끝에 붙은 가로선 = 모서리 → 박스 세로변 아님 ❌
    │           │
    └───────────┘
```

| | 범위 처리 | 목적 |
|---|---|---|
| `point_on_line` | 오차만큼 **넓힘** | 끝에 살짝 못 미쳐도 닿은 걸로 인정 |
| `_find_box_side` | 오차만큼 **좁힘** | 끝(모서리)은 일부러 제외 |

`drop`은 `is`로 후보에서 뺀다 (같은 **객체**만 제외).

| | 같은 객체인가 | 값이 같은가 |
|---|---|---|
| Java | `a == b` | `a.equals(b)` |
| Python | `a is b` | `a == b` |

## 4. Java 개발자용 파이썬 문법 메모

| 파이썬 | Java | 메모 |
|---|---|---|
| `[v for ln in lines for v in (ln.x1, ln.x2)]` | 이중 for + `add` | `for`를 왼쪽부터 읽으면 바깥 → 안쪽 |
| `[ln for ln in lines if 조건]` | `stream().filter(...).toList()` | |
| `max(length(ln) for ln in hs)` | `stream().mapToDouble(...).max()` | 대괄호 없으면 제너레이터 |
| `a, b, c, d = bbox(lines)` | `double[] r = ...; a = r[0] ...` | 튜플 언패킹 |
| `A if 조건 else B` | `조건 ? A : B` | 순서가 다름 |
| `if not my_list:` | `if (list.isEmpty())` | 빈 리스트는 False |
| `Line \| None` | nullable / `Optional<Line>` | |
| `x is None` | `x == null` | |
| `lambda ln: ln.y1` | `ln -> ln.y1` | |
| `sort(key=len, reverse=True)` | `sort(comparingInt(List::size).reversed())` | 제자리 정렬 |
| `@dataclass(frozen=True)` | `record` | 필드 재대입 금지, 리스트 내용은 변경 가능 |
| `_함수이름` | `private` (관례일 뿐) | 실제로 막지는 않음 |
| `a <= x <= b` | `a <= x && x <= b` | |
| 같은 이름 함수 재정의 | 컴파일 오류 | 파이썬은 **뒤의 것이 덮어씀** (오류 없음) |
