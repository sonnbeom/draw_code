# 도면 PDF → BOM 자동 추출: 설계 요약 (보고용)

## 1. 문제 정의
- **목표:** 도면 PDF에서 부품표(BOM)를 읽어 xlsx와 같은 구조로 출력한다.
- **어려운 점:** PDF 안의 글자가 텍스트가 아니라 **선(CAD 스트로크 폰트)**으로 그려져 있어 복사·텍스트 추출이 안 된다.
- **데이터:** PDF 820개 + 정답 json. 실제 입력도 같은 양식의 벡터 PDF.

```
PDF → 선 추출 → 표 찾기 → 칸 나누기 → 규칙 처리 → 글자 읽기(ML) → 조립 → xlsx
      └──────────────── 기하 규칙 (ML 없음) ─────────────┘
```

## 3. 해결책 · 트레이드오프 → 선택 + 이유

### P1. 글자 읽기 방식
| 안 | 장점 | 단점 |
|---|---|---|
| 이미지 + OCR | 기존 도구 사용 | 표 구조(칸 위치) 손실, 큰 도면은 글자가 1~2픽셀 |
| **선 좌표 + 직접 분류** | 좌표 정확, 표 구조를 같은 데이터로 처리 | 분류기를 직접 만들어야 함 |

**선택: 선 좌표.** 표 구조와 글자를 같은 데이터(선)로 함께 처리할 수 있다.

### P2. 표 찾기
| 안 | 장점 | 단점 |
|---|---|---|
| 헤더 글자로 판별 | 직관적 | 글자를 읽을 모델이 아직 없음 (모델 학습엔 BOM 표가 필요 → 순환) |
| ML 표 검출 | 범용 | 학습 데이터·비용 큼 |
| **기하 규칙 + 연결선** | 글자 없이 가능, 양식 고정이라 정확, 설명 가능 | 양식이 바뀌면 규칙 수정 |

**선택: 기하 규칙.** 길고 수평/수직인 선 → 격자 → **모부품 박스 연결선이 닿는 표 = BOM**. 화살표가 닿는 위치로 모부품 ↔ 수량 열을 매핑한다. 헤더 양식 3종은 헤더를 읽지 않으므로 별도 처리가 없다.

### P3. 글자 나누기
| 안 | 장점 | 단점 |
|---|---|---|
| 고정 폭으로 자르기 | 단순 | 글자 폭이 달라 경계가 어긋남 |
| **이어진 선 + x범위 겹침** | 실제 글자 경계를 따름, 도면 크기와 무관 | `"`처럼 떨어진 획은 쪼개질 수 있음 |

**선택: 이어진 선 + x범위.** 두 줄 품명은 x로만 정렬하면 위·아래 줄이 섞이므로 **y범위로 줄을 먼저 나눈 뒤** 줄마다 정렬해 이어 붙인다.

### P4. 학습 데이터 라벨링
| 안 | 장점 | 단점 |
|---|---|---|
| 사람이 직접 | 정확 | 수만 장이라 불가능 |
| **json 정답으로 자동** | 사람 손 없이 대량 생성 | 나누기가 틀리면 라벨도 틀림 |

**선택: 자동 라벨링.** 글자 묶음 수 ≠ 정답 글자 수인 칸은 버린다 (P8 검사 추가).

### P5. 글자가 아닌 선 (취소선·리비전 삼각형·연결선)
- **선택: 규칙으로 찾아 기록하고 지운 뒤 글자를 읽는다.** 남기면 글자들이 하나로 이어져 나누기가 깨진다.

| 대상 | 찾는 법 | 결과 |
|---|---|---|
| 취소선 | 행 가운데, 글자를 가로지르는 긴 수평선 | `[DEL]` |
| 리비전 삼각형 | 닫힌 세 선 + 정삼각형 + 크기(글자 높이 대비 비율) | 안 숫자를 내림차순 `(02,01)` |
| 연결선 | 표 찾기에서 이미 찾음 | 모부품 품명 위를 지나가므로 제거 |

- 삼각형 크기는 도면마다 달라(변 15.6~25) 고정값 대신 비율을 쓴다. 색(추가/삭제)은 출력에 필요 없어 구분하지 않는다.

### P6. 입력 형태 (정규화 + 래스터화)
- **정규화:** 글자 왼쪽 끝과 줄 바닥을 0으로 옮기고 줄 높이로 나눈다. 기준은 **행 전체**로 잡는다 (수량 칸의 "-" 혼자는 높이가 0이라 칸 단위로는 계산 불가, 수량 칸 4개 중 1개꼴).
- **래스터화:** 16×16 격자에 칠해 입력을 항상 256개로 고정한다.

| 격자 | 트레이드오프 |
|---|---|
| 4×4 | 너무 거침. "0"과 "O"가 같아짐 |
| **16×16** | 구분에 충분, 입력 수 적당 |
| 64×64 | 입력이 너무 많고 미세한 차이에 과민 |

### P7. 모델 선택
| 안 | 장점 | 단점 |
|---|---|---|
| k-NN | 학습이 없어 단순, 데이터 상태 진단 가능 | 예측이 느림, 칸별 중요도 모름 |
| 최근접 중심 | 아주 빠름 | 비슷한 글자에 약함 |
| **선형 (로지스틱 회귀/SVM)** | 구별되는 칸에 가중치 학습, 빠르고 가벼움 | 복잡한 패턴엔 한계 |
| 신경망 (MLP) | 표현력 높음 | 이 규모엔 과함, 튜닝 비용 |

**선택: 본 모델 = 선형, k-NN = 점검용, 신경망 = 사용 안 함.**
- CAD 폰트라 글자 모양이 거의 일정해서 선형으로 충분하다.
- 둘 다 낮으면 **데이터 문제**, k-NN만 높으면 **모델 문제**로 원인을 가른다.
- train/val/test = 70/15/15를 **PDF 단위**로 나눈다 (글자 단위로 섞으면 같은 도면의 글자가 양쪽에 들어가 점수가 부풀려짐).

### P8. 데이터 품질
- **문제:** 나누기 실수 두 개가 우연히 글자 수를 맞추면 개수 검사를 통과해 틀린 라벨이 섞인다.
- **선택:** 개수 검사(1차) + **크기 검사(2차)**. 같은 글자는 정규화 후 폭·높이가 거의 같으므로 크게 벗어난 카드는 버린다.

### P9. 모부품
- **품번:** 박스도 칸이므로 표 칸과 같은 방식으로 읽는다. index_no 칸은 일부 양식에만 있어 있으면 읽는다.
- **품명:** 박스와 같은 높이, 박스 오른쪽의 선을 모으고 연결선을 지운 뒤 읽는다.
- **rev:** 삼각형을 같은 높이에서 오른쪽으로 가장 가까운 대상(박스 또는 표 행)에 붙인다. 모부품/자부품 구분이 자동으로 따라온다.

### P10. 평가
- **문제:** 글자 정확도 99%여도 12글자 품번 칸은 0.99¹² ≈ 89%. 단위에 따라 점수가 크게 다르다.
- **선택:**
  - **행 정확도를 주 점수**로 삼는다 (실제 사용 단위). 칸·글자 정확도는 진단용.
  - 출력과 정답의 행은 **no로 짝짓는다** (도면 안 중복 0건). no 오독에 대비해 남은 행은 품번·순서로 2차 짝짓기.
  - 틀린 행은 앞 단계부터 판정해 **표 찾기 / 나누기 / 모델** 중 원인을 붙이고, 원인별 개수로 개선 우선순위를 정한다.
  - test PDF로 마지막에 한 번만 평가하고, 학습과 달리 개수가 안 맞는 칸도 버리지 않고 틀린 걸로 센다.

## 4. 남은 과제
- 설계 완료 → **구현 착수** (선 추출 → 표 찾기 → 규칙 처리 → 자동 라벨링 → 모델 → 출력·평가 순)
- 구현 중 실데이터로 확인할 것: 연결선 모양이 모든 도면에서 같은지, 삼각형 크기 비율·줄 간격 실제 값, 헤더 사선이 격자에 끼어드는지
