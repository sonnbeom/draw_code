# 도면 PDF → BOM 자동 추출: 설계 요약 (보고용)

## 1. 문제 정의
- **목표:** 도면 PDF에서 부품표(BOM)를 읽어 xlsx와 같은 구조로 출력한다.
- **어려운 점:** PDF 안의 글자가 텍스트가 아니라 **선(CAD 스트로크 폰트)**으로 그려져 있다. 그래서 복사나 텍스트 추출이 안 된다.
- **데이터:** PDF 820개와 정답 json. 실제 입력도 같은 양식의 벡터 PDF다.

## 3. 해결책 · 트레이드오프 → 선택 + 이유

### P1. 글자 읽기 방식
| 안 | 장점 | 단점 |
|---|---|---|
| 이미지 + OCR | 기존 도구를 쓸 수 있다 | 표 구조(칸 위치)가 사라진다. 작은 글자는 해상도 문제가 있다 |
| **선 좌표 + 직접 분류** | 좌표가 정확하고 표 구조를 그대로 쓸 수 있다 | 분류기를 직접 만들어야 한다 |

**선택: 선 좌표.** 표 구조와 글자를 같은 데이터(선)로 함께 처리할 수 있다.

### P2. 표 찾기
| 안 | 장점 | 단점 |
|---|---|---|
| ML로 표 검출 | 범용적이다 | 학습 데이터와 비용이 크다 |
| **기하 규칙** (길이, 수평/수직 → 격자 → 모부품 연결선) | 양식이 고정이라 정확하다. 설명할 수 있다 | 양식이 바뀌면 규칙을 고쳐야 한다 |

**선택: 기하 규칙.** 양식이 고정돼 있다. 표제란이나 리비전란처럼 격자가 비슷한 표는 모부품 연결선 유무로 배제한다.

### P3. 글자 나누기
| 안 | 장점 | 단점 |
|---|---|---|
| 고정 폭으로 자르기 | 단순하다 | 글자 폭이 달라 경계가 어긋난다 |
| **이어진 선 + x범위 겹침** | 실제 글자 경계를 따른다 | 글자가 닿거나 `"`처럼 떨어진 글자는 오류가 날 수 있다 |

**선택: 이어진 선 + x범위.** 오류는 P9 검사로 걸러낸다.

### P4. 학습 데이터 라벨링
| 안 | 장점 | 단점 |
|---|---|---|
| 사람이 직접 라벨링 | 정확하다 | 수만 장이라 불가능하다 |
| **json 정답으로 자동 라벨링** | 사람 손 없이 대량 생성할 수 있다 | 나누기가 틀리면 라벨도 틀린다 |

**선택: 자동 라벨링.** 글자 묶음 수와 정답 글자 수가 다른 칸은 버린다.

### P5. 취소선 [DEL]
- **선택: 규칙으로 판별한다.** 행 가운데 높이에서 글자를 가로지르는 긴 수평선을 찾는다. 찾으면 DEL로 기록하고 그 선을 제거한 뒤 글자를 읽는다.
- **이유:** 취소선은 위치가 분명해서 규칙으로 충분하다. 제거하지 않으면 글자 나누기가 깨진다.

### P6. 입력 형태 (정규화 + 래스터화)
- **정규화:** 글자 왼쪽 끝과 줄 바닥을 기준점(0)으로 옮기고, 줄 높이로 나눈다. 같은 글자는 어느 도면에서든 같은 패턴이 된다.
- **래스터화:** 16×16 격자에 칠해서 입력을 항상 256개로 고정한다.

| 격자 | 트레이드오프 |
|---|---|
| 4×4 | 너무 거칠다. "0"과 "O"가 같아진다 |
| **16×16** | 구분하기에 충분하고 입력 수도 적당하다 |
| 64×64 | 입력이 너무 많고 미세한 차이에 과민하다 |

### P7. 모델 선택
| 안 | 장점 | 단점 |
|---|---|---|
| k-NN | 학습이 없어 단순하다. 데이터 상태를 진단할 수 있다 | 예측이 느리다. 칸별 중요도를 모른다 |
| 최근접 중심 | 아주 빠르다 | "0"과 "O"처럼 비슷한 글자에 약하다 |
| **선형 (로지스틱 회귀/SVM)** | 구별되는 칸에 가중치를 학습한다. 빠르고 가볍다 | 복잡한 패턴에는 한계가 있다 |
| 신경망 (MLP) | 표현력이 높다 | 이 규모에는 과하다. 튜닝 비용이 든다 |

**선택: 본 모델은 선형, k-NN은 점검용, 신경망은 쓰지 않는다.**
- CAD 폰트라 글자 모양이 거의 일정해서 선형으로 충분하다.
- k-NN과 선형을 함께 돌리면 원인을 가를 수 있다. 둘 다 낮으면 **데이터 문제**, k-NN만 높으면 **모델 문제**다.

### P8. 평가
- **선택:** train/val/test를 70/15/15로 **PDF 단위**로 나눈다. 하이퍼파라미터는 val로만 고르고, test는 마지막에 한 번만 쓴다.
- **이유:** 글자 단위로 섞으면 같은 도면의 글자가 양쪽에 들어가 점수가 부풀려진다(데이터 누수).

### P9. 데이터 품질
- **문제:** 나누기 실수 두 개가 우연히 글자 수를 맞추면 개수 검사를 통과한다. 그러면 틀린 라벨이 섞인다.
- **선택:** 개수 검사(1차)에 더해 **크기 검사(2차)**를 한다. 같은 글자는 정규화 후 폭과 높이가 거의 같으므로, 크게 벗어난 카드는 이상치로 보고 버린다.
