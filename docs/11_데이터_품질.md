## 모델 결정 (Q32 이후 확정)

**내 의견.** 선형 모델이 낫다. 최근접 중심까지는 괜찮다. 신경망은 이 규모엔 오버스펙이다.

**평가.**
| 의견 | 평가 |
|---|---|
| 신경망은 오버스펙 | 맞다. CAD 폰트라 글자 모양이 거의 같아서 정확도가 오를 여지가 거의 없다 |
| 선형 모델이 낫다 | 좋은 선택. 가중치 학습, 빠르고 가벼움 → **본 모델** |
| 최근접 중심도 괜찮다 | 셋 중 가장 약함. 배점 없이 비교해서 "0"/"O"처럼 비슷한 글자에 약함 |

**결정.**
```
점검용:   k-NN (한 번 돌려서 기준점 확인)
본 모델:  선형 모델 (로지스틱 회귀 / SVM)
신경망:   안 함 (나중에 공부용으로만 선택)
```

## 왜 k-NN을 먼저 돌리나?

> 내 질문: "처음 한번 돌려보는 이유를 자세히 설명해줘"

점수가 낮을 때 **범인이 둘**이다.
```
[앞 단계: 데이터 만들기]                              [모델]
표 찾기 → 글자 분리 → 자동 라벨링 → 정규화 → 래스터화 → 학습 → 점수
       └──────────── 범인 1: 데이터 ────────────┘     └ 범인 2: 모델 ┘
```

- k-NN은 **학습 과정이 없다.** 저장해 두고 비교만 한다. 설정도 k 하나뿐이다.
- 그래서 k-NN 점수 ≈ **순수하게 "데이터가 얼마나 깨끗한가"**
- 비유: 체온계 두 개. 고장 날 수 없는 단순한 체온계로 한 번 더 재 보는 것

| k-NN | 선형 | 해석 | 고칠 곳 |
|---|---|---|---|
| 90% | 90% | 단순한 k-NN조차 못 맞힘 → 데이터가 깨짐 | 글자 분리, 라벨링, 정규화 |
| 99% | 90% | 데이터는 깨끗, 선형만 못함 | 모델 설정 |
| 99% | 99% | 둘 다 좋음 | 선형 채택 |

**덤.** k-NN(k=1)은 "이 글자랑 제일 닮은 게 이거"라고 **실제 예시**를 보여 준다. 틀린 글자의 이웃을 그려 보면 "라벨이 3인데 그림은 8" 같은 **잘못된 카드**를 직접 찾을 수 있다.

## 범인 1: 데이터가 적절하지 않다는 것

> 내 질문: "범인 1이 뭘 말하는지 자세히, 데이터가 적절하지 않다는 걸 풀어서"

**한 줄 정의.** 모델이 받는 **카드 앞면(그림)이나 뒷면(정답)이 잘못 만들어진 것**. 모델을 아무리 바꿔도 해결되지 않는다. 앞 단계 코드를 고쳐야 한다.

| 사고 | 무엇이 잘못됨 | 상태 |
|---|---|---|
| 1번: 나누기 오류 | 묶음이 잘못 나뉘어 엉뚱한 짝이 됨 → **정답지가 틀림** | 이해 완료 |
| 2번: 라벨 밀림 | 나누기는 맞는데 x 정렬이 꼬임 (두 줄 품명) → **정답지가 틀림** | 다음 차례 |
| 3번: 정규화 오류 | 높이를 잘못 재서 그림이 이상함 ("-"만 있는 칸, 두 줄 칸) → **문제지가 흐림** | 아직 |
| 4번: 래스터화가 너무 거칢 | 4×4면 "0"과 "O"가 같은 그림 → **문제지가 흐림** | 이해 완료 |

> 처음에 1~4번을 한꺼번에 들었을 때 4번만 이해했고 1~3번은 이해를 못 했음 → 하나씩 다시 함.

## 1번 사고: 나누기 오류

> 내 이해 (스스로 정리): "88250 칸을 찾는 건 일단 배제 → 88250을 이루는 선(1~47)을 가져옴 → 이어진 선 + x범위 겹침으로 나눔 → 여기서 잘못 나누는 게 문제인 상황" ✓

```
정답 "88250"
잘못 나눔: [8] [8] [25] [(] [)]    ← "2"와 "5"가 붙고, "0"이 위아래가 끊겨 쪼개짐
개수 5 == 5 → 개수 검사 통과!
짝짓기: [25]="2" ✗, [(]="5" ✗, [)]="0" ✗   → 틀린 카드가 학습 데이터에 섞임
```

- **원인은 ①나누기, 피해는 ④라벨**에서 드러난다
- 실수 두 개가 우연히 개수를 맞추면 Q13의 개수 검사를 그냥 통과한다
- 글자가 닿는 경우: 취소선 잔여, 좁은 글자 간격(case_0001), rev 삼각형 같은 다른 선

### Q34. 개수 검사 말고 이런 카드를 잡을 검사는?

**내 답.** "8-"랑 "8" 차이? 뭔 차이지? 답을 알려줘

**정리: 크기(폭·높이) 검사**
- 같은 CAD 폰트라 같은 글자는 정규화 후 **폭·높이가 거의 같다**
```
           폭      높이
"8"       0.6     1.0
"-"       0.5     0.05
"0"       0.6     1.0     (설명용 예시 숫자)
```
| 묶음 | 붙은 라벨 | 실제 폭×높이 | 정상 | 판정 |
|---|---|---|---|---|
| `[8-]` | "8" | **1.0**×1.0 | 0.6×1.0 | 너무 넓음 ✗ |
| `[(]` | "-" | 0.3×**1.0** | 0.5×0.05 | 대시인데 키가 큼 ✗ |
| `[)]` | "0" | **0.3**×1.0 | 0.6×1.0 | 너무 좁음 ✗ |

- 정상 크기는 **데이터 자체**로 안다: "8" 카드 수천 장 대부분은 맞으니, 동떨어진 값 = **이상치**
```
"8" 카드들의 폭: 0.59 0.60 0.61 0.60 ... 1.02 ← 이상치 → 그 칸 버림
```

```
자동 라벨링 검사
 1차: 묶음 개수 == 글자 수                     (Q13)
 2차: 묶음 크기가 그 라벨의 정상 범위 안인가     (Q34, 새로 추가)
```
