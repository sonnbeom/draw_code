# OCR 모델 학습 (미세조정) 계획

> 요약은 [20](20_OCR_흐름_이해.md). 이전 결정("지금은 미세조정하지 않는다", [설계 19](../설계/19_OCR_전략.md) 2절)을 바꿈

## 1. 문제와 결정
**문제.** 품명 `(DLX)` → `(OLX)` 5칸. 그림은 깨끗하고 `D`/`O`는 모양이 다른데 OCR이 잘못 읽음

| 후보 | 장점 | 단점 |
|---|---|---|
| 규칙 (`OLX` → `DLX`) | 바로 됨 | 본 단어만 고침. 다른 단어에서 또 틀림 |
| 여러 번 읽어 비교 ([22](22_합의와_점수.md)) | 틀린 걸 알아채고 다수결로 고침 | 덜 틀리게 만들지는 않음, 시간 ×5 |
| **학습 (미세조정)** | `D` 모양 자체를 배움 → 처음 보는 단어에도 통함 | 학습 도구 설치·시간, 과적합 위험 |

**결정 (2026-11-26). 학습한다.** 규칙은 나중에 또 다른 오독이 나오고, 학습 과정을 배우는 것도 목표. 비교(합의)와 역할이 달라 둘 다 씀 (학습 = 덜 틀리게, 비교 = 틀린 걸 알아채기)
- `0`/`O`는 모양이 같아 학습 대상이 아님 (형식 규칙 유지)

## 2. 큰 흐름
- 처음부터 만드는 게 아니라 **이미 잘 읽는 영어 인식 모델을 우리 그림으로 조금 더 학습**
```
① 데이터: 우리 줄 그림 + 그 줄의 정답 (샘플 0001~0600 학습 / 0601~0820 측정, 글자 사전과 같은 분할)
② 학습: 영어 PP-OCRv4 인식 모델을 이어서 학습 (PaddlePaddle CPU + PaddleOCR, 이 PC는 GPU 없음)
③ 변환: ONNX → bom/read_text/ocr.py 모델 경로만 교체 (엔진 감싸기 덕분에 나머지 코드 그대로)
④ 측정: 0601~0820 전/후 + 테스트 도면 그림 눈 확인
```
- 학습 도구는 프로젝트 환경(pyproject)이 아니라 **따로 만든 학습용 환경**에 설치 (설치 전 확인)

## 3. 줄별 정답 만들기
json은 칸 전체 한 문장뿐 → 지금 OCR 결과로 "몇 글자째에서 자르나"만 알아내고, 글자는 json에서 가져옴
```
OCR 줄1 "HEIGHT ADJUSTER LINK-FRT," = 25글자
json  "HEIGHT ADJUSTER LINK-FRT, | LH (DLX)"  → 줄1 / 줄2 정답 (OCR이 줄2를 OLX로 틀려도 정답은 json의 DLX)
```
- 자른 자리가 공백이 아니면 근처 공백에 맞추고, 그래도 이상하면 그 칸은 학습에서 뺌
- 취소·검수 칸은 뺌

## 4. 학습 설정
| 항목 | 정한 것 | 이유 |
|---|---|---|
| 글자 목록 | json에 나오는 글자(대문자·숫자·기호)만 | 소문자 오독이 구조적으로 사라짐 |
| 증강 | 같은 줄을 글자 크기·펜 굵기를 바꿔 그려 넣음 | 깔끔한 샘플에만 맞는 과적합을 줄임 |
| 과적합 확인 | 0601~0820(학습에 안 쓴 샘플) + 테스트 도면 눈 확인 | 테스트 도면은 정답 없음 → 방법은 구현 때 정함 |

## 5. 평가
- 칸 정답률 (지금 기준) + **CER** (글자 오류율 = 편집 거리 ÷ 정답 글자 수) + 혼동 글자 목록 (`D→O 5번` 식)
- 학습 전 숫자를 먼저 재 두고 비교

## 6. 나중: 능동 학습
- 검수자가 고친 칸을 학습 데이터로 다시 넣음 → 정답 없는 실제 도면에 맞춰 모델을 키우는 길 (운영 단계)

## 구현 때 확인
- PaddlePaddle CPU 설치 크기, CPU 학습 시간
- 학습한 모델 ONNX 변환이 RapidOCR에서 그대로 돌아가는지
