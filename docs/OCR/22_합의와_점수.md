# 여러 방법으로 읽어 비교하기 (앙상블·합의)와 점수

> OCR 결과마다 믿을 만한지 점수를 매겨, 낮은 것만 사람이 검수하게 한다. 요약은 [20](20_OCR_흐름_이해.md)

## 1. 문제: 엔진 자신감만으로는 틀린 걸 못 가린다
- RapidOCR 줄 점수 = 글자 점수의 **평균** → 한 글자만 틀리면 희석됨
- 실제 (샘플 0601~0820 품명): 틀린 `OLX` 줄 0.950 ×4 / 0.978, 맞은 줄 `LH (DLX)` 0.973, 다른 맞은 줄 최저 0.957 → 기준 하나로 못 가름
- 개선 후보: 글자별 점수의 **최솟값** (꺼낼 수 있는지 구현 때 확인)

## 2. 용어
| 용어 | 뜻 |
|---|---|
| 앙상블 | 여러 방법으로 읽은 결과를 합쳐 답을 정함 |
| 합의 | 결과가 서로 같은지 봄. 같으면 믿고, 갈리면 의심 |
| TTA (테스트 시 증강) | 같은 모델에 그림을 조금씩 바꿔 여러 번 넣는 것 (학습 때 바꿔 넣는 건 "증강") |
- 핵심: **서로 다른 실수를 하는 투표자**를 모아야 한다. 같은 실수를 하는 투표자는 여럿이어도 다수결로 틀린 답이 이김

## 3. 투표자 후보
| 종류 | 우리 후보 | 다른 실수를 하나 |
|---|---|---|
| A. 같은 모델, 그림만 바꿈 | 선분 좌표는 그대로, 그릴 때 글자 크기(28·32·36px)·펜 굵기(2·3·4px)만 바꿔 5장 | 4개 도면에서 오독 5줄 다 잡음 |
| B. 다른 모델·엔진 | 중국어+영어 모델, Tesseract 5, 학습한 모델 | 중국어 모델은 오독 5줄을 맞게 읽음, 대신 `-`→`一` 같은 다른 실수. Tesseract는 이 폰트로 안 돌려 봄 |
| C. 다른 방법 | 글자 사전 (그림이 아니라 선분 모양을 봄) | 가장 다름. 품명에는 안 맞음 |
- PaddleOCR은 RapidOCR과 **속 모델이 같아** 투표자로 의미 없음 (학습 도구로만 씀)
- 모델 두 개만이면 1:1로 갈릴 때 누가 맞는지 못 정함 → B는 A와 섞어 씀 (예: 지금 모델 5표 + 학습 모델 1표)

## 4. 결정: 틀은 하나, 투표자는 열마다
```
칸 → 여러 방법으로 읽음 → 전부 같음: 확정 / 갈림: 다수결 + 검수 표시
  I/NO·수량·품번: OCR 1회 + 글자 사전 (C)
  품명:           글자 크기·펜 굵기를 바꿔 5번 그려 읽기 (A), 학습 후 다른 모델 추가 검토 (B)
```
| 열 | A | B | C | 추천 |
|---|---|---|---|---|
| I/NO | 불필요 | 불필요 | 사전 100% | C |
| 수량 | 불필요 | 불필요 | 사전 11935/11935 | C |
| 품번 | 보조 | 보조 | 사전 2761/2761 (0/O 빼고) | C, 다르면 A |
| 품명 | 오독 5줄 다 잡음 | 중국어 모델도 5줄 맞음 | 안 맞음 | A (+ 학습 후 B) |
- 품명 투표는 **줄 문자열 전체** 단위. 줄 나누기·떨어진 `-` 찾기는 선분 계산이라 매번 같으므로 반복하지 않음 (그리기 + 읽기만 5번)
- 동점이면 지금 방식(32px·굵기 3) 결과를 우선

### 실제 예시: case_0647 행4 (정답 `4 / 88610-TMC00 / HEIGHT ADJUSTER LINK-FRT, LH (DLX) / -`)
| 열 | OCR | 글자 사전 | 처리 |
|---|---|---|---|
| I/NO | `4` | `4` | 같음 → 확정 |
| 수량 | `-` | `-` | 같음 → 확정 |
| 품번 | `8861O-TMCOO` | `88610-TMC00` | 0/O 차이만 → 같다고 보고 형식 규칙 |
| 품명 | `…LH (OLX)` | 못 읽음 | 크기·굵기 바꿔 5번 |

품명 둘째 줄: 32px·굵기3 `OLX` / 32px·굵기2 `DLX` / 32px·굵기4 `DLX` / 28px·굵기3 `OLX` / 36px·굵기3 `DLX` → 다수결 `DLX` ✓ + 갈렸으니 검수 표시

## 5. 측정
### 첫 측정 (0647·0706·0721·0800 품명 96줄)
- 89줄은 5개 결과가 모두 같음
- 갈린 7줄 = 틀린 5줄 전부 + 거짓 경보 2줄 (`M8X25`를 36px만 `M8X2S`)
- 다수결로 7줄 모두 정답. 자신감 점수로는 못 잡던 0.978 줄도 잡힘

### 220개 전체 (0601~0820)
품명 2761칸 / 4039줄, 취소·검수 칸 제외 (scratchpad 실험, 프로젝트 코드 안 바꿈)
| 항목 | 결과 |
|---|---|
| 정답률 | 1회 2756/2761 (99.82%) → 다수결 **2761/2761 (100%)** |
| 맞던 칸이 틀려짐 | 0 |
| 틀리던 칸이 고쳐짐 | 5 (`OLX` 5칸 전부) |
| 5개가 다 같은데 틀림 | 0 |
| 결과가 갈린 줄 = 검수 표시 칸 | 43 (1.6%) = 고쳐진 5 + 거짓 경보 38 |
| 시간 | 품명 읽기 칸당 178ms (1회의 약 10배), 도면당 약 2초 추가 |
- 거짓 경보 38칸은 대부분 두 종류: `M8X25`가 들어간 줄 (변형 하나가 `M8X2S`), 맞게 읽었지만 변형 일부가 `OLX`로 흔들린 `(DLX)` 줄 → `D`/`O`가 이 모델에서 아슬아슬하다는 증거 (학습 대상)
- 결론: 품명에 쓸 만함. 검수 43칸(1.6%)이 부담인지, 학습 후 몇 칸으로 줄어드는지는 학습 뒤 다시 잼

## 6. 점수 재료와 보정
| 재료 | 쓰는 법 |
|---|---|
| 투표 일치 수 | 5/5 높음, 3/5·4/5 낮음 → 검수. 다 같아도 틀릴 수 있음 (같은 착각) |
| 엔진 자신감 | 글자별 최솟값 (확인 필요) |
| 형식 규칙 | 품번 형식, 한 도면 안 품번 중복 0건, I/NO 순서, 수량은 숫자 또는 `-` |
| 줄 그림 높이 | 비정상이면 줄 나누기가 깨졌다는 신호 |
- 칸 점수 → 행 점수는 평균이 아니라 **최솟값** (한 칸만 틀려도 행 검수)
- 점수는 실제 정답률에 맞춰 **보정**해야 의미가 있음 ("0.9 = 90% 맞음") → 7단계 칸 신뢰도에서 위 재료를 합쳐 학습·보정
