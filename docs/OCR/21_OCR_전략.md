# OCR 전략

> 무엇을, 무엇으로, 어떻게 읽는가. 결정 근거·측정 기록은 [설계 19](../설계/19_OCR_전략.md), 요약은 [20](20_OCR_흐름_이해.md)

## 1. 원칙
- **위치·구조는 선 좌표, 글자 내용만 OCR.** 표·행·열·칸·줄은 선분으로 정확히 알기 때문에 OCR에 위치를 다시 찾게 하지 않는다
- OCR은 그림만 받으므로 선분 → 그림 변환은 우리가 직접 한다 (필요한 선분만 골라 그림)

## 2. 열마다 읽는 방법
| 열 | 지금 | 계획 (여러 방법으로 읽어 비교, [22](22_합의와_점수.md)) |
|---|---|---|
| I/NO | OCR 1회 | OCR 1회 + 글자 사전 1회 비교 |
| 수량 | OCR 1회 | OCR 1회 + 글자 사전 1회 비교 |
| 품번 | OCR 1회 + 0/O 형식 규칙 | OCR 1회 + 글자 사전 1회 비교 (0/O 차이는 같은 것으로) |
| 품명 | OCR 1회 | 글자 크기·펜 굵기를 바꿔 5번 그려 읽고 다수결 (사전은 품명에 안 맞음) |
- 글자 사전 = 샘플 0001~0600에서 "이 선분 모양은 이 글자"를 모은 것 (`bom/dictionary/glyph_dict.json`). 수량 11935/11935, 품번 2761/2761 (0/O 빼고), 품명 1138/2379 (긴 품명은 글자를 가로로 눌러 써서 모양이 안 맞음)

## 3. 그림 그리기 (`bom/read_text/cell_image.py`)
| 설정 | 값 | 이유 |
|---|---|---|
| 그리는 선분 | 칸 안 글자 선분만 (표 선·취소선·리비전 삼각형 뺌) | 필요 없는 선이 있으면 OCR이 헷갈림 |
| 글자 높이 `TEXT_PX` | 32px | 도면마다 글자 크기가 달라도 같은 크기로 (정규화). OCR은 20~30px 이상에서 잘 읽음 |
| 펜 굵기 `THICKNESS` | 3px | CAD 획이 가늘어서 조금 굵게 |
| 단위 | 칸 안의 한 줄 | 칸 통째보다 줄 단위가 잘 읽음 (4절) |

## 4. OCR 단위: 줄 모드
| 후보 | 결과 (0601~0650) |
|---|---|
| 칸 모드: 칸 그림 통째 → OCR이 글자 위치 찾기(검출) + 읽기(인식) | 품명 느슨 59.8%, 한 글자 칸(`1`, `-`)은 검출 못 함 |
| **줄 모드: 우리가 줄 나눔 → OCR은 읽기만** | 품명 느슨 69.7% → 이후 수정으로 99.8% (0601~0820) |

줄 모드 흐름:
```
칸의 글자 선분
  → 줄 나누기 split_by_valley (높이별 획 수의 골짜기에서 자름, 트러블슈팅 11~13 수정)
  → 줄마다: 떨어진 '-'는 선분으로 찾아 글자로 넣음 (bom/read_text/dash_split.py, OCR이 놓치던 것)
            나머지 조각만 그려 OCR
  → 형식 규칙 → 칸 글자
```

## 5. 형식 규칙 (OCR 결과 고치기, 지금은 `explore/measure_ocr/compare_readers.py` → `bom/`로 옮길 예정)
| 규칙 | 근거 |
|---|---|
| 대문자로 | json 1000개에 소문자 0개 |
| 줄 잇기: 윗줄이 글자에 붙은 `-`로 끝나면 공백 없이 (`(3-` + `STEPS`), 떨어진 ` -`면 공백 | 줄 끝 `-` 뒤 공백 오류 |
| 품번 0/O: `-` 바로 뒤이고 다음이 알파벳이면 `O`, 나머지 `0` | 0/O는 모양이 같아 그림으로 못 가림. json 통계로 정함, 규칙 밖 약 1.7% |

## 6. 엔진: RapidOCR + 영어 PP-OCRv4 인식 모델
- 고른 이유: 눌러 쓴 긴 품명에 강함, 프로세스 안에서 빠름, `uv add`로 설치, 미세조정 가능 (PaddleOCR로 학습 → ONNX)
- 영어 모델: 중국어+영어 기본 모델의 `-` → `一`, `)` → `）` 같은 오독이 사라짐
- `bom/read_text/ocr.py`가 엔진을 감싸서, 모델·엔진을 바꿔도 여기만 고친다
- 제외: EasyOCR (무거움, 느림), 클라우드 OCR (회사 도면이 밖으로 나감)

## 7. 표 전체 OCR (나중에 비교)
- 의견: 표 전체를 한 번에 OCR + 학습. 일반적으로는 규칙이 줄고 새 양식·스캔 도면에 강함
- 우리 조건에서 손해: 위치를 이미 정확히 아는데 OCR이 다시 추정, 이웃 칸 글자가 한 상자로 붙을 수 있음, 큰 표는 글자가 작아짐. 칸 모드도 줄 모드보다 낮았음 (4절)
