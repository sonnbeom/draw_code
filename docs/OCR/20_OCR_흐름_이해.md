## 1. OCR은 그림만 읽는다
- PDF 안에 글자 그림은 없다. **선분 좌표 숫자뿐**이다. 예: case_0647 행4 품명 둘째 줄 첫 글자 `L`
  ```
  선 1: (1399.4, 639.3) → (1399.4, 649.1)   세로선
  선 2: (1399.4, 649.1) → (1407.7, 649.1)   가로선
  ```
- OCR은 PDF·좌표를 직접 받지 못하고 **그림(픽셀)만** 받는다. "PDF를 OCR한다"는 도구도 속은 PDF → 그림 → OCR
- 그래서 "선분 → 그림" 변환이 반드시 필요하다. 이걸 우리가 직접 한다 (`bom/read_text/cell_image.py`)

## 2. 우리가 그림을 그리는 방식
| 방식 | 그려지는 것 |
|---|---|
| PDF 뷰어처럼 통째로 (pymupdf) | 표 선·취소선·리비전 삼각형까지 다 → OCR이 헷갈림 |
| **우리가 고른 선분만 (지금)** | 칸 안 글자 선분만, 취소선 뺌, 글자 높이 32px로 맞춤, 펜 굵기 3px, 한 줄씩 |

`L`을 그리는 과정 (이 도면 글자 높이 9.9 → 32px, 배율 3.23):
```
① 흰 도화지(픽셀 배열)
② 좌표 → 픽셀:  선 1 → (8, 8)→(8, 40),  선 2 → (8, 40)→(35, 40)
③ 검은 선 긋기 (펜 굵기 3px)
      █
      █        ← 32px
      █
      ████████
④ 이 그림을 OCR에 넘김
```

## 3. 줄 모드 흐름 (지금 방식)
```
칸의 글자 선분
  → 줄 나누기 (split_by_valley: 높이별 획 수의 골짜기에서 자름)
  → 줄마다: 떨어진 '-'는 선분으로 찾아 글자로 넣음 (bom/read_text/dash_split.py)
            나머지 조각만 그림으로 그려 OCR (위치 찾기 없이 읽기만)
  → 형식 규칙: 대문자 / 줄 잇기(붙은 '-'는 공백 없이) / 품번 0·O 위치 규칙
  → 칸 글자
```
- 위치·구조는 선 좌표, 글자 내용만 OCR (프로젝트 전략)
- I/NO·수량·품번은 선분 모양을 샘플에서 모은 **글자 사전**(4-1, `bom/dictionary/glyphs.py`)으로도 읽을 수 있다

## 4. 현재 결과 (샘플 0601~0820, 220개 도면, 취소·검수 칸 1181개 제외)
| 열 | 정답률 |
|---|---|
| I/NO · 수량 | 100% |
| 품번 | 느슨 100% (정확 98.7%, 틀린 36칸 전부 0/O) |
| 품명 | 99.8% (남은 5칸 전부 `(DLX)` → `(OLX)`) |
| 속도 | 칸당 18ms |

## 5. 남은 오류 두 종류
| 오류 | 성질 | 푸는 법 |
|---|---|---|
| `0` / `O` | 이 폰트에서 **모양이 똑같음** → 그림·선분·학습 어느 것도 구분 불가 | 형식 규칙 (품번: `-` 바로 뒤 + 다음이 글자면 O, 나머지 0) |
| `D` / `O` | 모양이 다름 (왼쪽 직선 / 곡선). 그림은 깨끗, OCR 순수 오독. `(DLX)` 275번 중 5번 틀림 | 여러 번 읽어 비교 ([22](22_합의와_점수.md)) + 학습 ([23](23_학습_계획.md)) |

## 6. 다음 순서
```
① 품명: 글자 크기·펜 굵기를 바꿔 5번 그려 읽고 다수결 → 220개 전체로 측정 (22)
② 평가 기준 추가: CER, 혼동 글자 목록 (23)
③ 학습 (미세조정): 학습 도구 설치 → 데이터 → 학습 → ONNX → 비교 (23)
④ (학습 후) 모델 앙상블: 두 번째 모델 골라 같이 투표 (22)
⑤ 점수 → 7단계 칸 신뢰도에서 합쳐 보정 (22)
⑥ 능동 학습 (운영 단계, 23)
```
