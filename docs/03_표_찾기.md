# 2. 표 찾기 (Q4~8)

> 앞 단계와의 연결: 선 좌표를 쓰기로 했다 → 그런데 선이 수천 개다. 그중 표는 어디에 있나?

## Q4. 표 칸 선만 거르려면?

선 수천 개(글자 선 / 표 칸 선 / 도형 선) 중에서 표 칸 선만 거르려면?

> 막혔던 지점: 처음엔 "모르겠다, 힌트 달라"고 했다. 실제 숫자 예시로 풀었다.
> 선 A: (100,200)→(103,206) 글자 '8'의 일부 / 선 B: (438,210)→(892,210) 표 테두리

**내 답.** B는 변화가 크고 A는 작다. (Q4-1) / B는 y가 제자리다. 표라면 길었을 것이다. (Q4-2)

**정리.** 표 선 후보 조건
- ① **길이가 길다** → 글자 선 제거
- ② **수평 (y1≈y2) 또는 수직 (x1≈x2)** → 원·비스듬한 선 제거
- "≈"인 이유: 실제 데이터는 210.00과 210.01처럼 미세하게 어긋날 수 있어서 **허용 오차**를 둔다

## Q5. 남은 긴 직선 중 표를 이루는 선은 어떻게 배치돼 있나?

**내 답.** 수평선들의 x 시작~끝이 위아래로 동일하다.

**정리.**
- 표의 수평선들은 시작 x·끝 x가 같고, 수직선들은 시작 y·끝 y가 같다 → **끝점이 맞닿은 격자**
- 이 조건으로 찾으면 BOM 표, 표제란, 리비전 기록란, 모부품 박스가 **모두 표 후보로 잡힌다.**
- (내가 "리비전 기록란도 밖에서 보면 표인데 왜 배제하냐"고 물어봄 → 아직 배제된 게 아니라 배제할 방법을 찾는 단계)

## Q6. 표 후보 중 BOM 표만 고르려면?

**내 답.** BOM 헤더에는 아이템 번호·부품 번호·부품 이름·수량이 있다. BOM 위에는 모부품이 있고, 표제란과 리비전 기록란에는 없다.

**정리.**
- 표제란 = 날짜·설계자·척도 같은 **도면 정보** (DAS 로고 부분) / 리비전 기록란 = 오른쪽 세로로 긴 칸
- BOM 단서: ① 헤더 글자 ② 위의 모부품 박스와 연결선

## Q7. 글자를 아직 못 읽는데, 지금 쓸 수 있는 단서는?

**내 답.** 모부품 박스의 x축 끝에서 나온 선이 자부품 표 y축 최상단과 만난다.

**정리.**
- 연결선 = 박스 오른쪽 끝에서 **수평선** → 꺾여서 **수직선** → 표 맨 위에 화살표로 닿음
- 전부 "수평/수직 + 끝점이 맞닿음"으로 표현 가능 → **글자를 읽지 않고 쓸 수 있는 단서 (②)**
- 헤더 글자(①)는 나중에 글자 읽기를 만든 뒤 **검증용**으로 쓴다

## Q8. 연결선이 알려주는 또 다른 정보는?

**내 답.** 모부품 개수? (잘 모르겠음) / (Q8-1) 맨 왼쪽 수량 칸의 "1"은 32100-TMC00A. 그 칸으로 화살표가 내려와서.

**정리.**
- 화살표가 표 위의 **어느 x 위치에 닿는지** → **모부품 ↔ 수량 열 매핑**
- "맨 아래 박스 = 맨 왼쪽 열" 같은 패턴보다 **도면이 직접 알려주는 연결**이 더 믿을 만하다

```
선 수천 개
  → [길고, 수평/수직]                     글자·도형 선 제거
  → [끝점이 맞닿은 묶음]                  표 후보들
  → [모부품 박스 + 연결선이 닿는 표]      BOM 표
  → [화살표가 닿는 x 위치]               모부품 ↔ 수량 열 매핑
  → [격자 선 좌표]                       셀(칸) 위치
```
여기까지는 **머신러닝 없이 기하 규칙만으로** 해결한다.
